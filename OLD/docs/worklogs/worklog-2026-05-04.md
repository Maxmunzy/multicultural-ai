## 오늘 작업 배경

윤정님 모델이 할 일을 `is_todo=False`로 올바르게 분류하고 있지만, 이것만으로는 제목을 따로 뽑아낼 수 없음.

```
[False] 2026 해원 놀이 한마당 안내          ← 제목인데 is_todo로는 구분 불가
[False] 재량휴업일(5/4) 긴급 돌봄 수요 조사
[False] 여름철 물놀이 사고 예방을 위한 안전수칙 안내
```

`is_todo`와 `is_title`은 서로 다른 차원의 라벨. 제목 추출 기능을 붙이려면 별도 분류 헤드가 필요함.

### 1. `scripts/prepare_todo_labels.py` — is_title 지원 추가

**Rule 기반 heuristic 추가** (`is_title_heuristic`):

```
조건 (모두 만족해야 True):
  - 텍스트 길이 10자 이상, 80자 이하
  - 문장 부호 (. ! ?) 없음
  - 항목 번호 (1. 가. 등) 로 시작하지 않음
  - "안내 / 공지 / 알림 / 통보 / 조사 / 신청 / 수납 / 모집" 으로 끝남
```

**Gemini 프롬프트 업데이트**:
- `is_title=true/false` 분류 기준 섹션 추가
- 출력 JSON 포맷에 `"is_title": false` 필드 추가
- Gemini 응답에 `is_title` 필드가 없으면 heuristic으로 자동 fallback

**출력 필드 변경**:
- `OUTPUT_FIELDS`에 `draft_is_title` 추가
- `make_rule_rows` / `make_gemini_rows` 모두 `draft_is_title` 포함하여 출력

**최종 학습 데이터 포맷**:
```json
{"text": "2026 해원 놀이 한마당 안내", "is_todo": false, "is_title": true}
{"text": "준비물을 챙겨주세요.", "is_todo": true, "is_title": false}
```

### 4. `model/extraction/file/predict.py` — is_title_heuristic / extract_title 추가

**왜 별도 함수로 분리했나:**
`split_sentences()` 내부의 `_HEADER_ONLY` 패턴이 제목 줄을 is_todo 후보에서 **조기 차단**. 차단된 줄을 다시 꺼낼 방법이 없으므로 `split_sentences()` 이전, 원문 줄을 직접 스캔하는 `extract_title()`을 독립 함수로 구현. `predict()` 반환 타입을 바꾸면 백엔드 `extractor.py`가 깨지므로 별도 함수로 노출.

**추가된 구성요소:**

```text
섹션 0 (모델 로드보다 앞)

_TITLE_CHECKPOINT_DIR   checkpoints/koelectra-title/ 경로
TITLE_THRESHOLD = 0.4   추론 임계값 (학습 후 임계값 분석으로 조정)

_load_title_model()     체크포인트 있으면 로드, 없으면 False
is_title_heuristic()    rule 기반 감지 (10~80자, 문장부호 없음, '안내/공지…'로 끝남)
extract_title()         ML 모델 우선, 없으면 heuristic fallback
```

**`extract_title()` 동작 방식:**

- `koelectra-title` 체크포인트가 있으면 → 전체 줄 스코어링 후 최고점 줄 반환
- 없으면 → heuristic으로 첫 번째 통과 줄 반환

**백엔드 연동 방법 (태수님 참고):**

```python
from model.extraction.file.predict import predict, extract_title

title = extract_title(notice_text)          # 제목 (없으면 None)
items = predict(notice_text, source=fname)  # 기존 그대로
```

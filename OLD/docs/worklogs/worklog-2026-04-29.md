## 역할 재분담

이전엔 윤정·경이가 같은 6-class 카테고리 분류를 *중복* 학습 중이었음. 정리:

- 윤정 v2 = 할일 추출 (binary 분류, BINARY_THRESHOLD=0.5)
- 경이 v2 = 6-class 카테고리 분류 (일정/준비물/제출/비용/건강·안전/기타)

분리 후 직렬 흐름이 깨끗해짐 ([3] 윤정 → [4] 경이).

## 핵심 설계 결정

| 결정 | 이유 |
| --- | --- |
| 추출 모델은 extractive only (binary or span) | seq2seq는 의역 위험. 학습 데이터 v1이 생성형 AI로 망한 패턴 반복 방지 |
| 응답 = `summary` 8슬롯 + `items` 구조 | 템플릿 슬롯 출력으로 안드 카드 UI에 직접 매핑 |
| URL/전화는 슬롯 단위 ko 그대로 + 본문은 placeholder 보호 | 세종님 요청. NLLB가 `031-627-7916` 같은 패턴 토큰화하면서 깨먹음 |
| 호스트 앱 의존 금지 (탑재형 정의) | "어떤 양식이든 정확히"의 핵심. 안드가 OCR한다는 우회는 가치 제안 무너뜨림 |
| 학습 파이프라인 vs 런타임 파이프라인 분리 | 학습 = 1회성 로컬 가공 (디지털 원본). 런타임 = 매 요청 (호스트 입력) |
| 단일학교 학습은 distribution shift지 overfitting 아님 | 0.70~0.78 OOD F1 예상은 실용 수준. 시연 점수에는 영향 없음 |

## 백엔드 파이프라인 (현재)

```text
호스트 앱 → POST /notice/upload (multipart)
           ↓
[1] services/parser.py — HWP/PDF/text → clean_text
[2] slot_extractor — 정규식 dates/times/amounts/urls/phones (summary 재료)
[3] extractor.extract_todos — 윤정 v2 KoELECTRA → list[YunjeongTodo]
[4] classifier.classify_category — 경이 simple/sklearn → Category
[5] translator — 슬롯별 i18n + glossary, NLLB는 placeholder 보호
[6] _build_summary + _build_item — AnalyzeItem 결합
[7] tts.generate_tts_file — gTTS
           ↓
JSON 응답 (summary 8슬롯 + items + tts_url)
```

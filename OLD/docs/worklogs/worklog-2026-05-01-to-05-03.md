## 핵심 구현 (세종)

### OcrActivity.java (신규 → 고도화)

- 카메라 촬영 → FileProvider URI → EXIF 회전 보정
- 전처리 4종 variant: raw / grayscale+CLAHE / warped(원근 보정) / warped+CLAHE
  - `warpDocument()`: Canny + 사각형 contour → `warpPerspective`로 문서 평면화
  - 문서 경계 미감지 시 raw·grayscale+CLAHE 2종으로 자동 fallback
- ML Kit Korean TextRecognition 각 variant 병렬 실행 → best 선택
- **2-pass 표 OCR**: 1차 전체 인식 → OpenCV 표 영역 감지 → 2차 표 crop 재인식 → 결과 병합
- Quality Gate Java 포팅 (표 유무에 따라 공식 전환)
  - 표 없음: `text_quality × 0.62 + pattern × 0.38 ≥ 0.80`
  - 표 있음: `text × 0.50 + pattern × 0.35 + table × 0.15 ≥ 0.80`
- 미통과 시: "원문 확인 필요" 경고 + 재촬영 / 강제 전송 선택 UI
- 업로드: `/notice/upload-self` (parent_id + file, X-User-Id = parentId)

### Quality Gate 임계값 변경

- 0.90 → **0.80** (실험 최고치 0.8242 기반 조정)
- 이유: 0.90은 현재 ML Kit 성능 범위 밖. 0.80이 실용적 기준.

### OCR 버튼 위치 변경

- 선생님 홈 → **학부모 홈** ("📷 종이 통신문 사진 번역")
- 이유: 종이 통신문 사진 촬영은 학부모 역할

### Android readTimeout

- 90s → **180s** (OCR 처리 + 번역 + 업로드 통합 흐름 커버)

### parser.py 변경 (태수님 피드백 반영)

- `_odt_to_text(mark_header=False)`: HWP 표 헤더 마킹 opt-in. True 시 첫 행에 `[헤더] cell1 | cell2` 접두사
- `_image_to_text()`: Tesseract 서버사이드 OCR 추가 (서버 fallback용)
- `IMG_EXTS = {".jpg", ".jpeg", ".png", ".webp"}`: parse_bytes_to_text에서 이미지 분기

### translator.py 변경

- `_OCR_NOISE`: 특수 기호(`□■▣▷◆` 등) 정규식 정제
- `_clean_for_translation()`: 번역 전 OCR 아티팩트 제거
- `translate_short_sentence()` 적용

### /notice/upload-self 엔드포인트 (태수님 구현, 세종 Android 연동)

- parent_id + file만 받음. teacher_id는 내부에서 parent_id로 대체
- 학부모가 종이 통신문을 직접 업로드하는 전용 경로

## 실험 — rule_split vs gemini_segment 품질 비교

**목적**: Gemini 세그멘테이션이 학습 데이터 품질에 얼마나 기여하는지 정량화  
**방법**: Gemini 처리된 원문 1,040개에 rule_split 재실행 후 동일 기준으로 비교  
**실행**: `prepare_todo_labels.py` 내부 함수 재활용, 추가 API 호출 없음

| 항목 | Gemini | Rule |
|------|--------|------|
| 원문당 평균 세그멘트 수 | **4.62개** | 3.71개 |
| Gemini가 더 세세하게 분리한 비율 | 58.8% | — |
| 평균 todo 라벨 수 | **1.36개** | 0.44개 |
| review_required 평균 | **0.01개** | 3.29개 |
| 세그멘트 평균 길이 | 39.5자 | 87.1자 |

**해석**
- Gemini는 의미 단위로 세세하게 분리(4.6개 vs 3.7개), 할 일 판단 3배 정확, 검수 요청 거의 없음
- Rule은 큰 덩어리 유지, todo 보수적 라벨링, review_required 3.29개 → 검수 부담 크고 학습 노이즈 우려
- **결론: 학습 데이터 품질 기준 Gemini 세그멘테이션 명확히 우위 → Gemini 한도 해소 후 나머지 93% 전량 Gemini 처리 예정**

> **윤정님 참고**: 현재 rule_split 상태 draft row는 review_required가 과다 표시됨. 모델 학습 전 Gemini 재처리 완료 후 데이터 사용 권장.

# v3.1 모델 생성 배경 — 문제 파악 및 해결 과정

**작성일**: 2026-05-06  
**담당**: 윤정

---

## 1. 발단 — 준비물 문장을 못 잡는 문제

v3 모델 운영 중 다음과 같은 실패 케이스가 보고됐다.

```
입력: "5. 준비: 간편한 복장, 운동화, 물통"
출력: ❌ (할 일로 탐지 안 됨)

입력: "② 당일 점심은 필요 없습니다"
출력: ❌ (할 일로 탐지 안 됨)
```

두 문장 모두 학부모가 직접 확인·행동해야 할 내용이지만 모델이 노이즈로 판정.

---

## 2. 원인 분석

### 2-1. BINARY_THRESHOLD 영향 확인

기존 threshold 0.65에서 이 패턴들의 모델 confidence가 0.65 미만으로 측정됨.  
threshold를 0.5로 낮추면 일부 문장은 통과하지만, 근본 원인은 다른 곳에 있었다.

### 2-2. mislabeling 전수조사

`v3_dual_labeled_clean.jsonl` (27,799개)에서 의심 패턴을 전수 조사.

**결과: 대부분의 False 라벨이 정확했다.**

| 패턴 | False 건수 | 실제 오라벨 |
|------|-----------|------------|
| `유의사항` 포함 | 43개 | 2개 (경계선) |
| `준비물:` 포함 | 3개 | 0개 |
| `지참` 포함 | 5개 | 0개 |
| `가져오` 포함 | 3개 | 0개 (다른 맥락) |

mislabeling이 아니라 **해당 패턴의 True 샘플 자체가 학습 데이터에 없거나 극소수**인 것이 문제.

### 2-3. 데이터 공백 확인

| 패턴 | 학습 데이터 내 True 샘플 수 |
|------|--------------------------|
| `번호. 준비:` (예: `5. 준비:`) | **0개** |
| `간편한/편안한 복장` | **1개** |
| 부정형 준비물 (`없음`, `불필요`) | 6개 (False가 12개로 역전) |
| 유의사항 실행형 (헤더 아닌 실제 행동 요구) | 12개 |

**결론: 모델이 해당 패턴을 학습한 적이 없어 노이즈로 처리하는 데이터 공백이 원인.**

## 3. 해결 방법 — 타겟 증강

### 3-1. 전략 선택

| 방법 | 검토 결과 |
|------|----------|
| 동일 하이퍼파라미터 재학습 | ❌ 거의 동일 결과 (데이터 변화 없음) |
| BINARY_THRESHOLD만 낮추기 | ⚠️ 즉시 효과 있으나 FP 증가, 임시방편 |
| mislabeling 수정 | ⚠️ 수정 대상 2개뿐, 효과 미미 |
| **실패 패턴 True 샘플 보강** | ✅ 근본 해결 |
| 모델 아키텍처 변경 | ❌ 과도한 작업, 현 데이터 수준에서 불필요 |

### 3-2. 증강 실행

`file/generate_v3_1.py` 스크립트 작성 → 7개 패턴 **448개** True 샘플 생성.

| 패턴 | 목표 | 생성 |
|------|------|------|
| P1 번호+준비물 (`N. 준비:`, `N. 준비물:`) | 100 | 100 |
| P2 간편한/편안한 복장 요청 | 80 | 80 |
| P3 부정형 준비물 (`없음`, `불필요`, `준비X`) | 70 | 68 |
| P4 유의사항 실행형 (행동 요청형) | 60 | 60 |
| P5 지참물 콤마 목록형 | 60 | 60 |
| P6 학부모 동반·참석 요청 | 40 | 40 |
| P7 당일 건강·안전 주의사항 | 40 | 40 |
| **합계** | **450** | **448** |

**품질 기준:**
- 실제 가정통신문 문체 (존댓말, 교육 어휘)
- 단순 템플릿 복사가 아닌 다양한 날짜·물품·학교 상황 조합
- 기존 학습 데이터와 중복 0개 확인

### 3-3. 병행 조치

BINARY_THRESHOLD 0.65 → **0.50** 낮춤.  
증강 데이터 재학습 시까지 즉시 recall 개선 효과를 확보하기 위한 임시 조치.  
v3.1 재학습 후 최적값 재탐색 예정.

## 4. 재학습 결과

|------|-----|-------|------|

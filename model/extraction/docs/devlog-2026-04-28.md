## 작업 배경

민경이님이 가정통신문 27장의 원문 텍스트를 추출하여 `notices_original2.csv / .jsonl` 로 제공했다.  
`original_text` 열은 채워져 있으나 `category`, `keywords`, `importance` 등 나머지 열은 모두 빈칸 상태였다.

이에 따라 두 가지 작업을 수행했다.

1. **`notices_labeled_v2.jsonl` 수정** — 기존 라벨 데이터에 원문 데이터와의 연결 고리(`original_id`) 추가
2. **`notices_original2.jsonl` 필드 채우기** — `category`, `keywords`, `importance` 세 열을 데이터 기반으로 자동 입력

> `action_required` 이후 열(`easy_korean`, `vietnamese`, `tts_target`)은 향후 서비스 확장 시 사용할 필드이므로 이번 작업에서 제외.

## 작업 1 — notices_labeled_v2.jsonl 에 원문 연결 필드 추가

### 배경

`notices_labeled_v2.jsonl` 의 각 항목은 문장 단위로 라벨이 붙어 있었으나,  
해당 문장이 27장 원문 중 어느 공문에서 왔는지 추적할 방법이 없었다.


## 작업 2 — notices_original2.jsonl 필드 채우기

### 방법 — 하이브리드 접근

현재 환경에 PyTorch 미설치로 KoELECTRA 모델 직접 실행 불가.  
아래 두 가지 방법을 공문 ID별로 선택 적용했다.

| 대상 | 방법 | 조건 |
|------|------|------|
| original IDs 9, 12~20, 23~27 | **labeled 데이터 집계** | `notices_labeled_v2.jsonl` 에서 동일 `original_id` 의 `is_todo=True` 문장들을 모아 집계 |
| original IDs 1~8, 10~11, 21 | **규칙 기반 추출** | labeled 매핑 없는 공문: 정규식으로 직접 추출 |
| original ID 22 | **규칙 기반(폴백)** | labeled 존재하나 `is_todo=True` 문장 없음(순수 정보성 공문) → 규칙 기반으로 폴백 |

### 채우는 방법 상세

**`category`** — 해당 공문에서 추출된 할 일 항목들의 카테고리를 중복 제거 후 쉼표로 연결  
예: `"제출, 건강·안전, 준비물"`

**`keywords`** — `importance ≥ 0.70` 인 할 일 문장 앞 60자를 최대 5개까지 ` / ` 로 연결

**`importance`** — 추출된 할 일 항목 중 최대 importance 점수 (문자열 형태로 저장)

### 규칙 기반 카테고리 분류 로직

```
비용     → MONEY_PATTERN(\d+원) 감지
제출     → "제출", "내주", "보내주" 키워드
준비물   → "준비", "가져", "챙겨", "구입", "지참" 키워드
건강·안전 → "안전", "건강", "마스크", "감염", "실종" 등 키워드
일정     → 날짜(X월 X일), 월(X월), "일시", "기간", "까지", "평가", "실시" 키워드
기타     → 위 어디에도 해당 없음
```

### importance 계산 기준

카테고리별 기본 점수에 가산 조건 적용 — `predict.py`의 `calc_importance()` 와 동일한 로직.

| 카테고리 | 기본 점수 | 긴급 키워드(+0.05) | 날짜 있음(+0.05) |
|---------|---------|-------------------|----------------|
| 제출     | 1.00    | ✓ | ✓ |
| 준비물   | 0.85    | ✓ | ✓ |
| 건강·안전 | 0.80   | ✓ | ✓ |
| 비용     | 0.75    | ✓ | ✓ |
| 일정     | 0.70    | ✓ | ✓ |
| 기타     | 0.50    | ✓ | ✓ |

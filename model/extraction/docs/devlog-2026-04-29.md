## 1. preprocess_txt_to_jsonl.py — 버그 수정 및 성능 개선

### 버그 1: predict.py 경로 오류 (치명)

kss 미설치 환경에서 fallback으로 `predict.split_sentences`를 불러올 때 경로가 잘못되어 있었다.

```python
# 수정 전 — model/extraction/predict.py 를 찾음 (존재하지 않음)
predict_path = _HERE.parent / "predict.py"

# 수정 후 — model/extraction/file/predict.py (실제 위치)
predict_path = _HERE / "predict.py"
```

kss가 없는 환경에서 전처리 실행 시 `AttributeError: 'NoneType' object has no attribute 'exec_module'` 로 터지던 버그.

### 버그 2: 급식 파일 과잉 스킵 (오분류)

파일명에 `"급식"` 키워드가 있으면 무조건 스킵하는 방식이었는데, 정보 전달 목적 파일도 함께 날아가고 있었다.

**잘못 스킵되던 파일 (7개)**
- `(가정통신) 교내 공사 진행상황 및 학교자체 급식일 변경 안내.txt`
- `2024년 급식실 공사기간 중 급식중단에 따른 학부모 의견조사 가정통신문.txt`
- `2025학년도 학교급식 식품알레르기 조사 안내문.txt`
- `2025학년도 우유급식 수요조사 안내문.txt`
- `2025학년도 3·4월 외부운반 위탁급식 가정통신문.txt` (2개)
- `2026학년도 우유급식 수요조사 및 식품알레르기 조사 안내문.txt`

**수정 방향**: 파일명 키워드 체크 제거, 내용 기반 패턴만 사용

```python
# 수정 전
_MEAL_NAME_KEYWORDS = ["급식"]   # 파일명에 "급식" 있으면 스킵

# 수정 후
_MEAL_NAME_KEYWORDS = []         # 파일명 기반 스킵 없음
```

실제 급식표에만 등장하는 내용 패턴(`에너지/단백질`, `①난류 ②우유`, `무상급식비:`, `N회 무상급식`)으로만 판별하면 정확하게 구분됨을 확인 (스킵 15개, 유지 7개 — 모두 정확).

### 성능 개선: 모듈 캐싱

281개 파일 처리 중 매 파일마다 `exec_module(mod)`으로 predict.py를 새로 로드하고 있었다. torch + transformers import가 매번 반복되어 전체 실행 시간이 수 분 이상 소요됐다.

```python
# 수정 전: 파일마다 exec_module → torch import 281회 반복
# 수정 후: 최초 1회 로드 후 캐시
_predict_mod = None

def _get_split_fn():
    global _predict_mod
    if _predict_mod is None:
        spec = importlib.util.spec_from_file_location("predict", _HERE / "predict.py")
        _predict_mod = importlib.util.module_from_spec(spec)
        spec.loader.exec_module(_predict_mod)
    return _predict_mod.split_sentences
```

## 2. predict.py — B단계 연동 출력 스키마 확장

A단계(윤정) → B단계(경이) 인터페이스를 구체화했다. 기존 포맷에서 필드 4개 변경·추가.

### 스키마 변경

```python
# 변경 전
{"text": str, "due_date": str|None, "has_money": bool}

# 변경 후
{
  "text":        str,       # 원문 문장 (유지)
  "source":      str|None,  # 출처 파일명 — 새로 추가
  "due_date":    str|None,  # YYYY-MM-DD or 상대표현 (유지, 연도 하드코딩 제거)
  "amount":      int|None,  # 실제 금액(원) — has_money bool에서 변경
  "confidence":  float,     # KoELECTRA 확률값 — 새로 추가
  "action_hint": str|None   # 납부/제출/신청/참여/준비/확인 — 새로 추가
}
```

### 변경 상세

| 항목 | 이전 | 이후 | 이유 |
|---|---|---|---|
| `has_money: bool` | True/False | `amount: int\|None` | B단계에서 실제 금액 필요 (`비용` 카테고리 분류 근거) |
| `due_date` 연도 | `_CURRENT_YEAR = 2026` 하드코딩 | `datetime.date.today().year` | 연도가 바뀌면 전부 오류 |
| `confidence` | 없음 | `float` (0.0~1.0) | B단계에서 낮은 확률 문장 별도 처리 가능 |
| `source` | 없음 | `str\|None` | 같은 통신문 내 문장 묶음 파악 가능 |
| `action_hint` | 없음 | 6종 키워드 | B단계 6-class 분류 힌트 (납부→비용, 제출→제출, 준비→준비물 등) |

### 내부 구조 개선

`is_likely_todo()`가 bool을 반환하는 구조에서는 confidence를 밖으로 꺼낼 수 없었다. `_classify()` 내부 함수를 분리해서 확률값을 직접 사용하도록 변경.

```python
def _classify(sentence: str) -> Optional[float]:
    """정규식 필터 → KoELECTRA 확률 반환. 필터에 걸리면 None."""
    ...

def is_likely_todo(sentence: str) -> bool:
    """외부 호환용 래퍼."""
    prob = _classify(sentence)
    return prob is not None and prob >= BINARY_THRESHOLD
```

### Bug 3 — 검수 상세 `원→won` 오탐

| 항목 | 내용 |
|------|------|
| **현상** | 본문에 통화 `원` 이 없는데 검수 상세에 `원→won` 매칭 표시 |
| **원인** | `"원하시는"`, `"원인"` 등 단어의 `원`에 substring 매칭 발생 |
| **수정 위치** | **`model/translation_tts/run_mvp_pipeline.py`** (본 노트북 범위 밖) |
| **수정 방법** | 글로사리 매칭 로직을 `str.contains('원')` → `re.search(r'\d[\d,]*\s*원', text)` 로 교체 |

> **확인**: `predict.py` 의 `MONEY_PATTERN = re.compile(r"(\d{1,3}(?:,\d{3})+|\d+)\s*원")` 은  
> 이미 숫자 선행 조건이 있어 extraction 레벨에서는 오탐 없음.

## 학습 코드 개선

기존 학습 결과가 목표치 미달이었다.

| 지표 | 기존 결과 | MVP 목표 |
|------|----------|---------|
| accuracy | 0.7500 | ≥ 0.80 |
| macro F1 | 0.5988 | ≥ 0.75 |
| 기타 F1 | 0.0000 | — |

**원인 분석**

- 클래스 불균형: `기타` 7개 vs `건강·안전` 35개
- 에폭 부족: 10 에폭으로는 희귀 클래스 수렴 불충분
- 학습률 스케줄: warmup 없이 일정 LR 사용

**수정 내역**

| 항목 | 변경 전 | 변경 후 |
|------|---------|--------|
| `num_train_epochs` | 10 | **15** |
| `learning_rate` | 3e-5 | **2e-5** |
| LR 스케줄러 | linear | **cosine** |
| warmup | 없음 | **`warmup_ratio=0.1`** |
| 손실 함수 | CrossEntropy (균등) | **WeightedCrossEntropy** (`balanced`) |

**WeightedTrainer 구현**

```python
from sklearn.utils.class_weight import compute_class_weight

_w = compute_class_weight("balanced", classes=np.arange(len(LABEL_LIST)), y=train_labels)
_class_weights = torch.tensor(_w, dtype=torch.float)

class WeightedTrainer(Trainer):
    def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
        labels = inputs.get("labels")
        outputs = model(**inputs)
        logits = outputs.get("logits")
        loss_fn = torch.nn.CrossEntropyLoss(weight=_class_weights.to(logits.device))
        loss = loss_fn(logits, labels)
        return (loss, outputs) if return_outputs else loss
```

예상 클래스 가중치 (100개 데이터 기준):

| 카테고리 | 샘플 수 | 가중치 (근사) |
|---------|--------|------------|
| 기타 | 7 | ~2.86 |
| 일정 | 18 | ~1.11 |
| 제출 | 18 | ~1.11 |
| 준비물 | 22 | ~0.91 |
| 건강·안전 | 35 | ~0.57 |

## 1. 문제 재진단: 왜 v1 KcELECTRA가 실패했나?

### 실패 원인 3가지

**원인 1: 데이터 부족 (가장 중요)**

| 모델 | 권장 최소 데이터 | v1 실제 데이터 |
|------|----------------|--------------|
| TF-IDF + LogReg | 50~100개/클래스 | 196개 (train) — 클래스당 평균 32개 |
| KcELECTRA (BERT 계열) | 100~200개/클래스 | 196개 — **클래스당 32개로 한참 부족** |

TF-IDF는 소량 데이터에서도 안정적이지만, KcELECTRA는 딥러닝 모델이라 데이터가 적으면 특정 클래스로 편향(class collapse)되거나 학습 자체가 안 됨.

**원인 2: 클래스 불균형 처리 안 함**

v1 train 데이터의 클래스 분포:
```
일정: 48개, 기타: 26개, 제출: 18개, 비용: 34개, 건강·안전: 33개, 준비물: 37개
```
`제출`(18개)과 `일정`(48개)의 차이가 2.7배.  
가중치 없는 CrossEntropyLoss를 쓰면 모델이 다수 클래스(`일정`, `건강·안전`)로 편향됨.  
실제로 v1 KcELECTRA는 `건강·안전` 하나만 예측했음.

**원인 3: 에폭 수 부족 + 학습률 너무 큼**

소량 데이터(196개, 클래스당 32개) + 5에폭 = 총 학습 스텝 약 61회(배치16 기준).  
딥러닝은 이 정도 스텝으로 수렴하기 어려움.  
LR=3e-5도 소량 데이터에서는 너무 커서 사전학습 가중치를 덮어쓸 수 있음.

## 2. 해결책: 자동 라벨링으로 데이터 확보

### 2-1. 왜 자동 라벨링인가?

윤정님이 추가한 새 데이터(`test_data.jsonl`, 5,560행)에는 `is_todo` 정보만 있고  
카테고리 라벨(`일정/준비물/제출/비용/건강·안전/기타`)이 없음.

선택지가 3개 있었다:
1. **수작업 라벨링**: 가장 정확하지만 시간이 너무 오래 걸림 (5,000행 × 10분 = 수백 시간)
2. **다른 ML 모델로 라벨링**: 기존 144개로 학습한 모델의 성능이 낮아 신뢰도 부족
3. **키워드 규칙 기반 자동 라벨링**: 빠르고, v3.csv로 정확도 검증 가능 ← **선택**

> "키워드 규칙이 100% 정확하지 않아도 괜찮다. 학습 데이터에 약간의 노이즈가 있어도  
> 데이터 양이 충분하면 딥러닝 모델은 이를 학습할 수 있다."

### 2-2. 규칙 설계 과정

**Step 1: 기존 v3.csv 분석**  
경이님이 직접 라벨링한 142개 문장을 카테고리별로 읽으면서 공통 키워드를 추출.

```
비용 문장들: "납부", "원을", "입금", "급식비", "참가비", "70,000원" ...
준비물 문장들: "지참", "챙겨", "착용", "도시락", "우산", "수영복" ...
제출 문장들: "제출", "동의서", "신청서", "설문", "작성하여" ...
건강·안전 문장들: "발열", "증상", "예방접종", "감염", "자가진단" ...
일정 문장들: "5월 20일", "오전 9시", "~까지", "졸업식", "운동회" ...
```

**Step 2: 우선순위 결정**  
"납부해 주세요, 5월 15일까지" → 날짜도 있고 납부도 있음.  
이런 경우 어떤 카테고리가 맞을까? → **비용**이 더 강한 신호.  
이유: 학부모 입장에서 행동을 유발하는 핵심 정보가 "납부"이기 때문.  
따라서 규칙 순서: **비용 > 준비물 > 제출 > 건강·안전 > 일정 > 기타**

**Step 3: 정규표현식 추가**  
`"70,000원"`, `"3만원"`, `"20,000원"` 같은 숫자+원 패턴은 고정 키워드로 못 잡음.  
`r"\d[\d,]*\s*원"` 정규식으로 이 모든 형태를 하나의 규칙으로 포착.

**Step 4: v3.csv로 정확도 검증**  
경이님이 직접 라벨링한 142개에 규칙을 적용 → 정답 121개 / 전체 142개 = **85.2%**  
오분류 21개 분석:
- "[일정→제출] 기한 내 신청하여 주시기 바랍니다": "기한 내 신청" 키워드가 제출에 걸림
- "[비용→제출] 입학 준비금 신청서를 제출하시면 10만 원이 지원됩니다": 제출 키워드가 비용보다 먼저 매칭
- "[건강·안전→기타] 아이가 아플 경우": "아플"은 규칙에 없어서 기타로 분류

85.2% 정확도는 "신뢰할 수 있는 자동 라벨" 기준(75% 이상)을 충족.

## 3. KcELECTRA v2: v1 실패 원인별 대응

| 실패 원인 | v1 | v2 개선 |
|----------|-----|--------|
| 데이터 부족 | train 196개 | **train 556개 (2.8배)** |
| 클래스 불균형 | 일반 CrossEntropyLoss | **가중치 손실 (WeightedCELoss)** |
| 에폭 부족 | 5 에폭 | **15 에폭** |
| 학습률 | 3e-5 | **2e-5 (안정적)** |
| 워밍업 | 10% | **20% (초반 가중치 보호)** |

### 가중치 손실 함수 계산법

```python
class_counts = [train_df["category"] == lbl).sum() for lbl in LABELS]
# [105, 64, 109, 78, 90, 110] (일정, 준비물, 제출, 비용, 건강·안전, 기타)

total = sum(class_counts)  # 556
weight[i] = total / (6 * class_counts[i])
```

계산 결과:
- 준비물(64개): weight = 556 / (6 × 64) = **1.448** ← 높은 패널티
- 기타(110개): weight = 556 / (6 × 110) = **0.842** ← 낮은 패널티

이렇게 하면 모델이 "적은 클래스를 틀리면 더 큰 손실"을 받아 편향을 방지.

→ 이 점 때문에 KcELECTRA가 Simple보다 높게 나오려면 **0.79 + 0.05 = 0.84 이상** 필요.

## 6. 심사위원 예상 질문 & 답변

**Q. 왜 자동 라벨링을 선택했나요?**  
A. 수작업으로 5,000개 문장을 라벨링하면 수백 시간이 필요합니다. 키워드 규칙 기반 자동 라벨링은 도메인 지식(학교 공지 문장의 특징)을 코드로 구현한 것이며, v3.csv로 검증해 85.2% 정확도를 확인했습니다. 약간의 노이즈가 있어도 데이터 양(4.9배)이 더 중요합니다.

**Q. 규칙 정확도 85.2%면 14.8%가 틀리는데 괜찮은가요?**  
A. 딥러닝 모델은 어느 정도의 노이즈에 견고합니다. 14.8% 노이즈는 학습 데이터에 있는 것이고, 테스트 데이터는 split_v2.csv의 10% (69개)인데 이 중 자동 라벨 비율이 높아 테스트도 어려워집니다. 그래도 데이터 양이 4.9배 늘어난 효과가 훨씬 큽니다.

**Q. 키워드 순서를 어떻게 결정했나요?**  
A. v3.csv를 직접 읽으면서 카테고리별 핵심 단어를 분석했습니다. "납부"는 비용에서만 나타나지만 날짜 표현은 여러 카테고리에 섞일 수 있어 일정을 후순위에 뒀습니다. 오분류 사례를 보면서 경계가 애매한 경우들을 파악했고, 이를 통해 규칙 순서의 타당성을 검증했습니다.

**Q. v1 KcELECTRA가 왜 실패했나요?**  
A. 데이터 부족(클래스당 32개)과 클래스 불균형 처리 미흡이 주요 원인입니다. BERT 계열 모델은 최소 클래스당 100개 이상이 필요한데, 32개로는 사전학습 지식을 우리 도메인에 맞게 조정(파인튜닝)하기에 부족했습니다. 특히 가중치 없는 손실함수를 쓰니 모델이 `건강·안전` 하나로만 예측하는 클래스 붕괴가 발생했습니다.

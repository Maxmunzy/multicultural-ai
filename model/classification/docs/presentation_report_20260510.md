## 2. 각각의 목적이 다른 두 가지 베이스라인

베이스라인은 보통 "내가 만든 고급 모델이 정말 필요한가?"를 증명하기 위한 가장 단순하고 합리적인 기준 모델이다.  
ML에서 baseline은 **무엇을 증명하려고 하느냐에 따라 의미가 달라진다.**  
이 프로젝트에서는 목적이 서로 다른 두 가지 베이스라인을 사용했다.

### 2-1. 메인 비교 베이스라인: Simple (TF-IDF + LogReg) vs KcELECTRA v3_2

**목적:** "왜 굳이 무겁고 비용이 드는 딥러닝(트랜스포머) 모델을 써야 하는가?"에 대한 당위성 증명  
→ **Global Baseline** vs 딥러닝(트랜스포머): 최종 성능 입증용 / 투자 및 아키텍처 정당화

#### 왜 TF-IDF + Logistic Regression을 베이스라인으로 삼는가?

실무에서 새로운 AI 모델을 도입할 때 가장 먼저 받는 질문은 **"그냥 간단한 머신러닝 돌리면 안 돼?"** 다.  
TF-IDF와 Logistic Regression은 가볍고, 빠르며, 연산 비용이 거의 들지 않는 전통적인 자연어 처리(NLP) 기법이다.  
이것을 글로벌 베이스라인(최소한의 기준점)으로 삼는 것은 AI 업계의 표준 방식이다.  
→ **의사결정자 설득용:** "트랜스포머를 쓰는 것이 합리적이다"는 아키텍처 정당화에 활용

```

    → auto_label_from_new_data_20260504.py

    → 규칙 정확도 85.2% 검증 완료

  - train 12,759 / val 1,596 / test 1,593 (총 15,948행)
    ↓
[모델 학습] beomi/kcelectra-base 파인튜닝
  - 가중치 손실 함수 (weighted CrossEntropyLoss)

```

### 수동 라벨링 대신 자동 라벨링을 선택한 이유

윤정님이 추가한 새 데이터(`test_data.jsonl`, 5,560행)에는 `is_todo` 정보만 있고  
카테고리 라벨(`일정/준비물/제출/비용/건강·안전/기타`)이 없었다.

선택지 3가지를 검토했다:

| 방법 | 장점 | 단점 | 채택 여부 |
|-----|------|------|---------|
| 수작업 라벨링 | 정확도 최고 | 5,000행 × 수분 = 수백 시간 (현실적으로 불가) | ✗ |
| 기존 ML 모델로 라벨링 | 자동화 가능 | 기존 144개로 학습한 모델 성능이 낮아 신뢰도 부족 | ✗ |
| **키워드 규칙 기반 자동 라벨링** | 빠르고, 정확도 검증 가능 | 14.8% 노이즈 | **✓** |

> "키워드 규칙이 100% 정확하지 않아도 괜찮다. 학습 데이터에 약간의 노이즈가 있어도  
> 데이터 양이 충분하면 딥러닝 모델은 이를 학습할 수 있다."

### 자동 라벨링 규칙 설계 과정

**Step 1: 142개 문장을 카테고리별로 공통 키워드를 추출.

```
비용 문장들:    "납부", "원을", "입금", "급식비", "참가비", "70,000원" ...
준비물 문장들:  "지참", "챙겨", "착용", "도시락", "우산", "수영복" ...
제출 문장들:    "제출", "동의서", "신청서", "설문", "작성하여" ...
건강·안전 문장들: "발열", "증상", "예방접종", "감염", "자가진단" ...
일정 문장들:    "5월 20일", "오전 9시", "~까지", "졸업식", "운동회" ...
```

**Step 2: 정규표현식 추가**  
`"70,000원"`, `"3만원"`, `"20,000원"` 같은 숫자+원 패턴은 고정 키워드로 잡을 수 없다.  
`r"\d[\d,]*\s*원"` 정규식으로 이 모든 형태를 하나의 규칙으로 포착했다.

**Step 3: 정확도 검증**  
라벨링된 142개에 규칙 적용 → 정답 121개 / 전체 142개 = **85.2%**  
85.2% 정확도는 신뢰할 수 있는 자동 라벨 기준(75% 이상)을 충족한다.

## 4. 사용 모델 및 구현 방식 (핵심 기능)

### `src/classifier_simple.py` — 베이스라인 (TF-IDF + Logistic Regression)

**왜 TF-IDF인가?**
- TF-IDF는 각 단어가 문서에서 얼마나 중요한지 숫자로 나타냅니다
- "납부", "입금", "원" 같은 단어가 **비용** 카테고리에서 많이 나오면 높은 점수를 받음
- GPU 없이 CPU에서 수십 ms만에 실행 — 백엔드 서버 부담 없음

**왜 char_wb n-gram인가?**
- 한국어는 "납부해" "납부하여" "납부하시기" 등 동사 변형이 많음
- 글자 단위 2~4글자 조합(`ngram_range=(2,4)`)으로 형태소 변형 문제 해결
- 예: "납부" → "납부", "부하", "부해", "납부하" 등으로 분해해 학습

**사용법:**
```bash
cd model/classification
python src/classifier_simple.py          # 학습 + 저장
python src/classifier_simple.py --eval   # 테스트 평가
```

## Kcelectra 모델을 선택한 이유

1. 데이터 양이 많을 수록 simple(베이스 모델)보다 성능이 향상됨
2. 학교 도메인 어휘 OOV 문제 해결 (subword tokenization)
3. A단계 base 모델과 같은 koelectra ─ backbone 공유 가능
   → 백엔드 RAM 중복 로드 회피 
4. 한국어 특화 사전학습 모델 
5. ELECTRA 구조: BERT보다 학습 효율이 2~3배 좋음

### `src/classifier_kcelectra.py` — KcELECTRA 추론 모듈

**중요:** 이 파일은 **추론만** 합니다. 학습은 `notebooks/01_train_kcelectra.ipynb`에서.

### `src/predict.py` — 백엔드 진입점

**왜 이 파일이 중요한가?**

- 내부에서 어떤 모델을 쓸지 결정하는 로직 포함
- `model="auto"`로 설정하면 체크포인트 유무에 따라 자동 선택

## 5. 정량 지표 — 왜 Accuracy가 아닌 Macro F1인가?

### 문제: 기타 클래스가 test set의 46.5%를 차지

| 카테고리 | test 건수 | 비율 |
|---------|---------|------|
| 기타 | 741건 | **46.5%** |
| 제출 | 316건 | 19.8% |
| 건강·안전 | 214건 | 13.4% |
| 일정 | 194건 | 12.2% |
| 비용 | 84건 | 5.3% |
| 준비물 | 44건 | 2.8% |
| **합계** | **1,593건** | **100%** |

Accuracy를 쓰면 모델이 모든 문장을 "기타"로만 예측해도 **46.5%** 를 얻는다.  
이 수치는 모델이 실제로 분류를 잘 한다는 의미가 아니다.

### 해결: Macro F1 (클래스 균등 가중치)

Macro F1은 **모든 클래스에 동일한 가중치**를 부여한다.  
"준비물(44건)"과 "기타(741건)"를 같은 비중으로 평가하므로,  
소수 클래스를 무시하는 모델을 걸러낼 수 있다.

**Macro F1 계산 방식:**
$$\text{Macro F1} = \frac{1}{6} \sum_{i=1}^{6} F1_i$$

## 7. 실패 사례

### 7-1. v1 KcELECTRA 학습 실패 (Macro F1 0.5310 — Simple 0.8450보다 낮음)
--> 여기서 V1은 첫번째 버전을 의미. 총 v1 → v2 → v3 크게 세 버전이 존재.

v1에서 KcELECTRA는 특정 클래스로 편향(class collapse)되거나 학습 자체가 안 됐다.  
`제출` 카테고리에서 F1 = 0.0000 (4건 전부 오분류) 이 발생했다.

**원인 1: 데이터 부족 (가장 중요)**

| 모델 | 권장 최소 데이터 | v1 실제 데이터 |
|------|----------------|--------------|
| TF-IDF + LogReg | 50~100개/클래스 | 196개 (train) — 클래스당 평균 32개 |
| KcELECTRA (BERT 계열) | 100~200개/클래스 | 196개 — **클래스당 32개로 한참 부족** |

TF-IDF는 소량 데이터에서도 안정적이지만, KcELECTRA는 딥러닝 모델이라 데이터가 적으면  
특정 클래스로 편향(class collapse)되거나 학습 자체가 안 된다.

**원인 2: 클래스 불균형 처리 미흡**

v1 train 데이터의 클래스 분포:
```
건강·안전: 48개, 일정: 34개, 제출: 33개, 준비물: 37개, 기타: 26개, 비용: 18개
```
최대(건강·안전 48개) vs 최소(비용 18개) 차이가 **2.67배**.  
가중치 없는 CrossEntropyLoss를 쓰면 모델이 다수 클래스(`건강·안전`)로 편향된다.  
실제로 v1 KcELECTRA는 `건강·안전` 하나만 예측하는 경향을 보였다.

**원인 3: 에폭 수 부족 + 학습률 너무 큼**

소량 데이터(196개, 클래스당 32개) + 5에폭 = 총 학습 스텝 약 **65회** (배치16 기준).  
딥러닝은 이 정도 스텝으로 수렴하기 어렵다.  
LR=3e-5도 소량 데이터에서는 너무 커서 사전학습 가중치를 덮어쓸 수 있다.

## 8. 한계와 향후 개선점

**참고 파일:** `devlog_20260510.md`

### Confusion Matrix (KcELECTRA v3_2, test 1,593건)

```
              일정  준비물   제출   비용  건강·안전   기타
일정  (194):   159     0    10     1      2      22
준비물  (44):     1    38     0     0      1       4
제출  (316):     3     0   254     4      1      54
비용   (84):     0     1     4    68      1      10
건강·안전(214):   0     0     5     0    188      21
기타  (741):    10     4    28    11     61     627
```

아래 순위는 v3_2 Confusion Matrix와 per-class F1에서 **직접 도출**한 것으로,  
v3_2가 수렴한 지점에서의 병목을 기준으로 한다.

---

### 1순위 한계 — 기타·건강·안전 레이블 경계 기준 부재

Confusion Matrix에서 가장 큰 단일 오분류: **기타 → 건강·안전 61건**

```
기타 → 건강·안전: 61건  ← 전체 행렬 대각선 제외 최대값
건강·안전 → 기타: 21건  ← 역방향 오분류도 존재
```

이 양방향 혼동이 건강·안전의 Precision을 **0.7402(6개 중 최저)**까지 끌어내리며,  
결과적으로 건강·안전 F1이 0.8034(최저)로 **Macro F1 전체를 하락**한다.

문제의 본질은 "기타 데이터 다양성 부족" 보다,  
**기타와 건강·안전을 구분하는 라벨링 기준 자체가 없다**는 것이다.  
"수영 수업 안전 주의사항 안내"처럼 두 카테고리 모두에 해당할 수 있는 문장에 대해  
기준이 없으면 라벨러마다 다르게 분류하고, 그 모호함이 학습 데이터에 섞인다.

**향후 개선:** 기타-건강·안전 경계 기준 명문화 → 재라벨링

---

### 2순위 한계 — 기타 클래스 불균형 (test set 46.5%)

기타가 test set의 **46.5%** (741/1,593건)를 차지한다.

```
클래스 가중치 (학습 시):
  기타:     0.3587  (가장 낮음 = 가장 많은 샘플)
  준비물:   5.9399  (가장 높음 = 가장 적은 샘플)
  비용:     3.1411
  건강·안전: 1.2378
  일정:     1.3702
  제출:     0.8418
```

weighted loss를 적용했음에도 이 정도 불균형이면  
모델은 기타 패턴을 과도하게 내재화하고, 나머지 5개 카테고리 학습이 상대적으로 빈약해진다.

"기타 데이터 다양성 부족"이라는 표현은 사실 이 불균형 문제에 더 가깝다.  
데이터가 부족해서가 아니라, **기준 없이 쌓인 기타 데이터가 너무 많아서** 문제다.

**향후 개선:** 기타 비율 축소 또는 하위 카테고리 분리 검토

---

### 3순위 한계 — 기타 개념 자체의 모호함

기타가 특정 카테고리 하나가 아닌 **전체 카테고리로 고루 오분류**된다.

```
기타 → 건강·안전: 61건
기타 → 제출:      28건
기타 → 비용:      11건
기타 → 일정:      10건
기타 → 준비물:     4건
```

반대로 다른 카테고리도 기타로 흘러들어온다.

```
제출     → 기타: 54건 (제출 오분류 중 85.7%)
일정     → 기타: 22건 (일정 오분류 중 62.9%)
건강·안전 → 기타: 21건
비용     → 기타: 10건
```

기타는 "그 외 모든 것"이라는 정의상 명확한 의미 경계가 없다.  
모델이 학습할 **결정 경계(decision boundary) 자체가 불분명**하다.  
1순위와 연결되는 근본 원인이다.

**향후 개선:** 1순위 기준 정의와 연동해 근본적으로 해결 필요

---

### 추가 한계 — 비용(F1 0.8095)

비용은 건강·안전과 달리 단일 원인이 아닌 **복합 문제**다.

```
비용 → 기타:  10건  (recall 문제)
기타 → 비용:  11건  (precision 문제)
```

기타-비용 간 양방향 혼동이 존재하지만 규모가 작다.  
동시에 test가 **84건**밖에 없어 수치 신뢰도 자체가 낮다 (1건 오분류 = F1 약 ±1.2%p).  
순수 데이터 양 문제라기보다 **경계 혼동 + 소규모 데이터가 겹친 복합 원인**으로 판단한다.

**향후 개선:** 비용 카테고리 데이터 추가 수집 (test 84건 수준은 수치 신뢰도 부족)

> "KcELECTRA v3_2의 카테고리별 F1을 분석한 결과, 기타(F1 0.8479)는 6개 카테고리 중 3위로 성능 한계의 직접 원인이 아니었다. Macro F1을 실제로 끌어내리는 건 건강·안전(F1 0.8034, Precision 0.7402)이며, 그 원인은 기타→건강·안전 오분류 61건(Confusion Matrix 내 대각선 제외 최대값)으로 확인된다. 이는 두 카테고리 사이의 라벨링 기준이 부재하여 학습 데이터에 경계 모호함이 섞인 결과다. 2순위는 기타가 test set의 46.5%를 차지하는 클래스 불균형, 3순위는 기타 개념 자체의 모호함으로, 이 세 요인 모두 v3_2 Confusion Matrix와 per-class F1에서 직접 도출된 v3_2 모델 자체의 수렴 지점 한계다."

## 9. 발표용 예상 Q&A

**Q. 왜 자동 라벨링을 선택했나요?**  
A. 수작업으로 5,000개 문장을 라벨링하면 수백 시간이 필요합니다. 키워드 규칙 기반 자동 라벨링은 도메인 지식(학교 공지 문장의 특징)을 코드로 구현한 것이다. 약간의 노이즈가 있어도 데이터 양(4.9배)이 더 중요합니다.

**Q. 규칙 정확도 85.2%면 14.8%가 틀리는데 괜찮은가요?**  
A. 딥러닝 모델은 어느 정도의 노이즈에 견고합니다. 14.8% 노이즈는 학습 데이터에 있는 것이고, 테스트 데이터는 split_v3의 10%(1,593건)입니다. 데이터 양이 22.9배 늘어난 효과가 훨씬 큽니다.

**Q. 키워드 순서를 어떻게 결정했나요?**  
A. "납부"는 비용에서만 나타나지만 날짜 표현은 여러 카테고리에 섞일 수 있어 일정을 후순위에 뒀습니다.

**Q. v1 KcELECTRA가 왜 실패했나요?**  
A. 데이터 부족(클래스당 32개)과 클래스 불균형 처리 미흡이 주요 원인입니다. BERT 계열 모델은 최소 클래스당 100개 이상이 필요한데, 32개로는 사전학습 지식을 우리 도메인에 맞게 조정(파인튜닝)하기에 부족했습니다. 특히 가중치 없는 손실함수를 쓰니 `건강·안전` 하나로만 예측하는 클래스 붕괴가 발생했습니다.

**Q. Accuracy 대신 Macro F1을 쓰는 이유는?**  
A. 기타 클래스가 test set의 46.5%를 차지합니다. Accuracy를 쓰면 모든 문장을 기타로 예측해도 46.5%를 얻습니다. Macro F1은 모든 클래스에 동일한 가중치를 부여하므로 소수 클래스(준비물 2.8%)를 무시하는 모델을 걸러낼 수 있습니다.

## 10. 결론 요약

> KcELECTRA v3_2는 Simple(TF-IDF + LogReg) 베이스라인 대비 Macro F1 **+0.0784** (0.7590 → 0.8374) 향상을 달성했다.  
> 전 카테고리(6/6)에서 KcELECTRA가 Simple을 앞서 **트랜스포머 모델 도입의 당위성**을 수치로 입증했다.

> 그 배경에는 기타-건강·안전 사이의 **라벨링 기준 부재**라는 구조적 문제가 있다.

## 평가 지표 설명

### Macro F1 (메인 지표)
- 6개 카테고리 각각의 F1을 구한 뒤 **평균**
- 클래스 불균형에 강함 (특정 클래스가 많아도 편향 없음)
- **0.8 이상이면 좋은 성능**

### F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
- **Precision (정밀도):** "비용이라고 예측한 것 중 실제로 비용인 비율"
- **Recall (재현율):** "실제 비용인 것 중 비용이라고 맞춘 비율"
- F1은 이 둘의 균형

### Confusion Matrix
행 = 실제 카테고리, 열 = 예측 카테고리  
대각선이 클수록 좋음 (맞게 분류한 것들)

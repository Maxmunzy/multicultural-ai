### 우선순위 3 — Simple 앙상블 *(내일, 빠른 방법)*

목표가 5% 이상 차이라면, KcELECTRA + Simple 소프트 투표 앙상블로 즉시 달성 가능:

```python
# evaluate_compare_v3_20260505.py에 추가
def ensemble_predict(texts, kc_model, simple_model, weight_kc=0.7):
    kc_probs  = kc_model.predict_proba(texts)      # (N, 6)
    s_probs   = simple_model.predict_proba(texts)   # (N, 6)
    combined  = weight_kc * kc_probs + (1 - weight_kc) * s_probs
    return combined.argmax(axis=1)
```

> 앙상블은 시연용이 아닌 최종 서비스 모델 확정 전에 사용하는 방법.

## 8. v4 / v5 파인튜닝 추가 시도 결과

> 위 섹션 6의 **우선순위 1** (하이퍼파라미터 조정)을 두 번 시도했으나 모두 v3보다 성능이 낮게 나왔다.

### 8-1. v4 시도 (`07_train_kcelectra_v4_20260505.ipynb`)

| 변경 항목 | v3 | v4 |
|---|---|---|
| LR | 2e-5 | **3e-5** |
| weight_decay | 없음 | 0.01 |
| warmup_ratio | 0.1 | 0.15 |

**결과:** v3(0.8545)보다 낮음.
**원인 분석:** ELECTRA는 LR 변화에 민감한 모델. 3e-5는 사전학습된 인코더 표현을 과도하게 흔들어 학습 불안정 유발.

### 8-2. v5 시도 (`08_train_kcelectra_v5_20260505.ipynb`)

| 변경 항목 | v3 | v5 |
|---|---|---|
| LR | 2e-5 | 2e-5 (유지) |
| label_smoothing | 없음 | **0.1** |
| LR schedule | linear | **cosine** |
| weight_decay | 없음 | 0.01 |
| epochs | 20 | 25 |

**결과:** v3(0.8545)보다 낮음.
**원인 분석:** label_smoothing이 val/test 갭을 줄이기보다 전체 학습을 약화시킨 것으로 보임. ELECTRA 계열 모델은 label_smoothing에 오히려 민감하다는 보고가 있음.

### 8-3. 공통 교훈

> v3의 설정(LR=2e-5, linear, 가중치 CE 손실)이 이 데이터셋에서 가장 안정적.
> 이후 시도는 **손실 함수 자체를 바꾸거나 레이어별로 다른 LR을 주는** 방향으로 전환해야 함.

### 10-3. 누적 교훈 — 하이퍼파라미터 튜닝의 한계

v4, v5, v6을 통틀어 모두 v3보다 낮은 성능이 나온 패턴은 다음을 시사한다:

> **KcELECTRA가 현재 데이터셋(기타 630건)에서 구조적 한계에 도달.**
> 하이퍼파라미터·손실 함수 변경은 경계 모호한 기타 클래스 자체의 데이터 부족 문제를 해결할 수 없다.
> 더 이상의 파인튜닝 시도보다 **데이터 보강이 유일하게 남은 실질적 해결책이다.**

| 시도 | 핵심 가설 | 왜 효과가 없었는가 |
|---|---|---|
| v4 (LR 3e-5) | 학습 속도 올리기 | ELECTRA 인코더가 destabilize됨 |
| v5 (label_smooth + cosine) | val/test 갭 줄이기 | label_smooth가 ELECTRA 학습 자체를 약화 |
| v6 (FocalLoss + 차등 LR) | 기타 클래스 집중 | 기타 데이터 자체가 부족해 어떤 손실 함수도 학습할 패턴이 없음 |

## 11. 우선순위 2 (즉시 시행): 기타 클래스 데이터 보강

> 앙상블 포함 지금까지의 모든 접근이 기타 클래스 F1=0.67 벽을 넘지 못한 원인은
> **기타 학습 데이터(630건) 자체의 다양성 부족**이며, 데이터 보강이 유일한 남은 해결책이다.

### 11-4. 라벨링 기준 (기타 vs 다른 카테고리 구분법)

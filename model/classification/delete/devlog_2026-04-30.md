## 1. 작업 배경 및 목표

### 왜 이 작업이 필요한가?
다문화가정 학부모를 위한 가정통신문 자동 분석 시스템에서, 윤정님 모델이 중요 문장을 추출한 뒤 그 문장이 **어떤 종류의 정보인지 분류**해주는 역할이 필요하다.

예를 들어:
- "체험학습 비용 20,000원을 납부해 주세요." → **비용**으로 분류
- "운동회는 10월 5일 오전 9시에 시작합니다." → **일정**으로 분류
- "도시락과 물을 꼭 챙겨주세요." → **준비물**로 분류

이 분류 결과가 최종 앱 화면에서 학부모에게 보여질 때 카테고리 아이콘으로 표시되고, TTS(음성 출력) 순서 정렬에도 활용된다.

### 목표 클래스 (6개)
```
일정  /  준비물  /  제출  /  비용  /  건강·안전  /  기타
```

## 2. 데이터 구축 — `data/notice_sample_v3.csv`

### 데이터 규모
- **총 142개 문장**, 카테고리별 약 20~25개씩 균등 구성
- 실제 갈산초등학교 가정통신문 텍스트에서 영감을 받아 작성
- 카테고리별 특징 키워드를 충분히 포함

### 데이터 예시

| text | category |
|------|----------|
| 현장체험학습은 5월 20일(화) 오전 9시에 출발합니다. | 일정 |
| 체험학습 당일 도시락과 물을 준비해 주세요. | 준비물 |
| 동의서를 작성하여 3월 20일까지 담임선생님께 제출해 주세요. | 제출 |
| 현장체험학습 참가비 3만 원을 3월 20일까지 납부해 주세요. | 비용 |
| 발열·기침 증상이 있는 경우 등교를 자제해 주세요. | 건강·안전 |
| 궁금한 사항은 담임선생님께 문의해 주세요. | 기타 |

### 왜 이렇게 구성했나?
- **일정**: 날짜 표현, 시간, 행사명 키워드에 집중
- **준비물**: "지참", "준비", "챙겨", "착용" 등 행동 동사 포함
- **제출**: "제출", "동의서", "설문", "신청서" 등 문서 관련 키워드
- **비용**: "원", "납부", "입금", "지원금" 등 금액 관련
- **건강·안전**: "증상", "예방접종", "마스크", "안전" 등 신체 관련
- **기타**: 안내 문구, 문의 사항, 홈페이지 공지 등

## 3. 베이스라인 구현 — `src/classifier_simple.py`

### 선택한 모델: TF-IDF + Logistic Regression

**이유:**
1. **GPU 불필요** — 백엔드 서버(CPU)에서 부담 없이 동작
2. **빠른 추론** — 문장 1개당 수십 ms 이내
3. **해석 가능** — 어떤 단어가 분류에 영향을 줬는지 확인 가능
4. **데이터 적을 때도 안정적** — 딥러닝보다 소량 데이터에 강함

**TF-IDF 설정 상세:**

| 파라미터 | 값 | 이유 |
|---------|-----|------|
| `analyzer` | `"char_wb"` | 한국어 형태소 변형 대응 (글자 단위) |
| `ngram_range` | `(2, 4)` | 2~4글자 조합으로 어근 정보 포착 |
| `max_features` | `30,000` | 메모리와 속도의 균형점 |
| `sublinear_tf` | `True` | 빈도 폭발 억제 (log 스케일) |

**Logistic Regression 설정:**

| 파라미터 | 값 | 이유 |
|---------|-----|------|
| `C` | `1.0` | 기본 정규화 (오버피팅 방지) |
| `class_weight` | `"balanced"` | 클래스 불균형 자동 대응 |
| `random_state` | `42` | 재현성 |
| `multi_class` | `"multinomial"` | 6-class 다중 분류 |

**성능 목표:** Macro F1 ≥ 0.75 (시연 최소 기준)

**학습/저장/로드 구조:**
```
train() → checkpoints/simple_tfidf_logreg.pkl 저장
load_pipeline() → 첫 호출 시 pkl 로드 (이후 캐시 재사용)
predict_simple(text) → {"category": ..., "confidence": ..., "probs": {...}}
```

## 4. KcELECTRA 모듈 구현 — `src/classifier_kcelectra.py`

### 왜 KcELECTRA인가?

**기술적 배경:**
- KcELECTRA = Korean + ELECTRA 구조
- ELECTRA는 BERT의 변형으로, Discriminator 방식으로 학습 → 같은 데이터에서 BERT보다 2~3배 효율적
- `koelectra-small-v3-discriminator` 사용 → 파라미터 수 적어 CPU 서버 배포 가능

**윤정님 모델과의 관계:**
```python
# 이상적인 메모리 효율 구조 (공유 백본)
shared_encoder = AutoModel("monologg/koelectra-small-v3-discriminator")
윤정_head = BinaryHead(shared_encoder)        # 할일 추출
경이_head = MulticlassHead(shared_encoder, 6)  # 카테고리 분류
```
같은 backbone을 공유하면 경이님 모델 추가에 따른 RAM 증가가 최소화됨.

**파일의 역할:**
- 이 파일은 **추론(Inference)만** 담당
- 학습은 `notebooks/01_train_kcelectra.ipynb`에서 수행 (GPU 필요)
- `is_ready()` 함수: 파인튜닝 체크포인트 존재 여부 확인
- 체크포인트 없으면 `predict.py`가 자동으로 simple fallback 선택

## 5. 백엔드 진입점 — `src/predict.py`

### 핵심 함수: `predict_one()`

```python
predict_one(
    text: str,
    model: str = "simple",  # "simple" | "kcelectra" | "auto"
    today: datetime.date = None,
    explain: bool = False
) → dict
```

**`model="auto"` 동작 흐름:**
```
kcelectra 체크포인트 있음?
    YES → kcelectra로 예측
    NO  → simple로 예측 (안전한 fallback)
```

**백엔드 코드가 이 함수를 어떻게 쓰는지:**
```python
# backend/app/services/classifier.py
result = predict_one(text, model="simple", today=today, explain=False)
label = result.get("category", "")
return Category(label)
```

## 6. 데이터 분할 — `scripts/split_dataset.py`

### 왜 분할 파일을 고정해야 하는가?

**공정한 비교의 핵심 원칙:**
> 베이스라인과 KcELECTRA가 **완전히 동일한 데이터**로 학습하고 평가해야 한다.

매번 다른 분할을 사용하면 성능 차이가 모델 능력 때문인지 데이터 분할 운 때문인지 알 수 없다.

**분할 전략:**
- Stratified Split: 각 카테고리에서 동일 비율로 추출
- Seed = 42: 언제 실행해도 같은 결과 보장
- 비율: Train 80% / Val 10% / Test 10%

**생성 파일 컬럼:**
```
text, category, split
"운동회는 10월...", "일정", "train"
"도시락을 준비...", "준비물", "val"
"납부 금액은...", "비용", "test"
```

## 7. 성능 비교 — `scripts/evaluate_compare.py`

### 평가 지표 선택 이유

**왜 Accuracy가 아닌 Macro F1인가?**
- Accuracy = 전체 정답 비율 → 특정 클래스(예: "기타")가 많으면 그것만 맞춰도 높은 점수 가능
- Macro F1 = 6개 클래스 각각의 F1 평균 → 클래스 불균형에 공정

**Per-class F1의 활용:**
```
"비용은 F1 0.92로 잘 잡는데, 건강·안전은 F1 0.45로 부족하다"
→ 건강·안전 카테고리 데이터 추가 필요!
```

**채택 기준:**
- KcELECTRA Macro F1 ≥ Simple Macro F1 + 0.05 → KcELECTRA 채택
- 그 미만 → Simple 유지 (안정성 우선)

## 8. KcELECTRA 학습 노트북 — `notebooks/01_train_kcelectra.ipynb`

### GPU가 필요한 이유
- KcELECTRA는 약 1400만 개의 파라미터
- CPU에서 학습 시 수 시간 소요
- GPU(T4)에서는 약 20~30분

### Colab 사용 방법
1. [colab.research.google.com](https://colab.research.google.com) 접속
2. 노트북 업로드 → `01_train_kcelectra.ipynb`
3. 런타임 → 런타임 유형 변경 → **T4 GPU** 선택
4. `data/notice_sample_v3.csv`와 `data/split_v1.csv` 파일 업로드
5. 모든 셀 순서대로 실행

### 학습 과정 (셀 순서)
| 단계 | 내용 |
|------|------|
| 셀 1 | 라이브러리 설치 (Colab 시 주석 해제) |
| 셀 2 | 시드 고정 + GPU 확인 |
| 셀 3 | 설정값 (에폭, 배치 크기 등) |
| 셀 4 | 데이터 로드 |
| 셀 5 | Dataset + DataLoader 생성 |
| 셀 6 | 모델 초기화 |
| 셀 7 | Optimizer + Scheduler |
| 셀 8 | 학습 루프 (Best 모델 자동 저장) |
| 셀 9 | 학습 곡선 그래프 |
| 셀 10 | Test 세트 최종 평가 |
| 셀 11 | Confusion Matrix 시각화 |

### 주요 하이퍼파라미터

| 파라미터 | 값 | 의미 |
|---------|-----|------|
| `MAX_LEN` | 128 | 토크나이저 최대 토큰 수 |
| `BATCH_SIZE` | 16 | 한 번에 처리할 문장 수 (OOM 시 8로 변경) |
| `EPOCHS` | 5 | 전체 데이터를 5번 반복 학습 |
| `LR` | 3e-5 | 학습률 (KcELECTRA 권장값) |
| `WARMUP_RATIO` | 0.1 | 처음 10% 스텝은 학습률 서서히 증가 |

**왜 Linear Warmup인가?**
파인튜닝 초반에 학습률이 너무 크면 사전학습 가중치가 망가진다.
처음 10% 스텝을 서서히 올려 안정적으로 시작하고, 이후 선형으로 감소시킨다.

## 9. 시각화 노트북 — `notebooks/02_evaluate_compare.ipynb`

### 생성되는 차트 4종

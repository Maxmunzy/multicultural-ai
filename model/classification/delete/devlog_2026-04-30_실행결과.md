## Step 3 — KcELECTRA 파인튜닝 결과

**환경:** Google Colab T4 GPU  
**베이스:** `monologg/koelectra-small-v3-discriminator`  
**설정:** EPOCHS=5, BATCH_SIZE=16, LR=3e-5, MAX_LEN=128

| 카테고리 | Precision | Recall | F1 |
|--------|-----------|--------|----|
| 일정 | 1.00 | 0.80 | 0.89 |
| 준비물 | 1.00 | 0.25 | 0.40 |
| 제출 | 0.00 | 0.00 | **0.00** |
| 비용 | 0.00 | 0.00 | **0.00** |
| 건강·안전 | 0.32 | 1.00 | 0.48 |
| 기타 | 0.00 | 0.00 | **0.00** |
| **Macro F1** | **0.39** | **0.34** | **0.29** |

### 왜 이렇게 낮은가?

KcELECTRA가 `건강·안전` 하나만 예측하고 있다 (recall=1.00, precision=0.32).  
이를 **클래스 붕괴(class collapse)** 라고 부른다.

**원인 분석:**

1. **데이터 부족** — 학습 데이터 196개는 트랜스포머 파인튜닝에 너무 적다.
   일반적으로 클래스당 최소 100~200개, 전체 1000개 이상이 권장됨.

2. **클래스 불균형** — train 데이터에서 `건강·안전`(33개)이 `제출`(18개)의
   거의 2배. `class_weight` 설정을 안 해서 다수 클래스로 편향됨. (태수님이 추천: 모델이 다수 클래스로 편향 -> 가중치(class_weight='balanced' 또는 weighted CE loss)미적용 시 비용/준비물 F1 0.5~0.65 예상 (지금 simple 비용 0.667 정도), 그래서 클래스 불균형 처리를 위해 class_weight 또는 oversampling 적용 권장.)

3. **학습률 & 에폭** — 소량 데이터에서 LR=3e-5, 5에폭은 수렴 보장이 어려움.

4. **워밍업 불충분** — 196개 × 5에폭 = 980 스텝 중 워밍업 98 스텝(10%)은
   적절하지만, 전체 스텝 자체가 너무 적어 안정적 학습이 어려움.

### KcELECTRA 채택 판정

> ΔMacro F1 = 0.29 − 0.84 = **−0.55**  
> 채택 기준: ΔF1 ≥ +0.05  
> **결과: 채택 불가 → 베이스라인(Simple) 유지**

## `evaluate_compare.py` 상세 설명

### 역할
베이스라인(Simple)과 KcELECTRA를 **동일한 test 데이터로** 평가하고  
결과를 JSON·CSV로 저장하여 정량 비교하는 스크립트.

### 실행 방법
```bash
cd model/classification
python scripts/evaluate_compare.py              # test split
python scripts/evaluate_compare.py --split val  # val split으로 평가
```

### 내부 동작 순서

```
1. evaluate_simple("test")
   ├── split_v1.csv에서 test 행만 로드
   ├── simple_tfidf_logreg.pkl 불러오기
   ├── 예측 → classification_report 계산
   └── {"model":"simple", "macro_f1":..., "per_class":..., "confusion_matrix":...} 반환

2. evaluate_kcelectra("test")
   ├── [우선] eval_results_kcelectra.json 있으면 그대로 사용 (torch 없어도 가능)
   ├── [없으면] kcelectra_ready() 확인 → torch + 체크포인트 둘 다 있어야 True
   ├── 준비됐으면 test 데이터 추론 → _make_result() 계산
   └── 없으면 {} 반환 (스킵)

3. save_and_compare(simple_res, kcelectra_res)
   ├── data/eval_results_simple.json 저장
   ├── data/eval_results_kcelectra.json 저장 (kcelectra_res 있을 때만)
   ├── data/eval_comparison_summary.csv 저장
   └── ΔMacro F1 출력 + 채택 판정 출력
```

### 출력 파일 설명

| 파일 | 내용 | 용도 |
|------|------|------|
| `eval_results_simple.json` | Simple 모델 전체 결과 | 02 노트북 시각화용 |
| `eval_results_kcelectra.json` | KcELECTRA 전체 결과 | 02 노트북 시각화용 |
| `eval_comparison_summary.csv` | 두 모델 Macro F1 요약 | 발표 근거 자료 |

### 주요 판정 로직

```python
delta = kcelectra_res["macro_f1"] - simple_res["macro_f1"]
if delta >= 0.05:
    print("KcELECTRA 5%+ 향상: 채택 권장!")
else:
    print("5% 미만 향상: Simple 유지 고려")
```

## KcELECTRA 성능 개선 방향

### 방향 2 — 클래스 가중치 추가

노트북 Cell 6 모델 초기화 직후에 추가:

```python
from torch.nn import CrossEntropyLoss

# 소수 클래스에 가중치 부여
class_counts = [train_labels.count(l) for l in LABELS]
total = sum(class_counts)
weights = torch.tensor(
    [total / (len(LABELS) * c) for c in class_counts],
    dtype=torch.float
).to(DEVICE)
loss_fn = CrossEntropyLoss(weight=weights)
```

학습 루프(Cell 8)에서 `outputs.loss` 대신 `loss_fn(outputs.logits, labels)` 사용.

### 방향 3 — 학습률 & 에폭 조정

| 파라미터 | 현재 | 권장 (데이터 부족 시) |
|--------|------|--------------------|
| EPOCHS | 5 | **10~15** |
| LR | 3e-5 | **1e-5** (더 작게) |
| BATCH_SIZE | 16 | **8** (안정성↑) |
| WARMUP_RATIO | 0.1 | **0.2** (워밍업 늘리기) |

### 방향 4 — 데이터 증강

# 팀 진행 브리프

## 현재 프로젝트 핵심

우리 프로젝트의 핵심은 다문화 가정 학부모가 학교 알림, 특히 가정통신문의 내용을 쉽게 이해하고 필요한 행동까지 이어질 수 있도록 돕는 AI 시스템을 만드는 것이다.

현재 단계에서는 서비스를 크게 확장하기보다, 아래 핵심 흐름이 실제로 동작하는 MVP 뼈대를 만드는 것이 가장 중요하다.

1. 학교 알림 텍스트 입력
2. 핵심 정보 추출
3. 카테고리 분류
4. 쉬운 한국어 / 베트남어 안내
5. TTS 음성 안내
6. 실기기에서 결과 확인

## 강사님 피드백 반영 방향

강사님 피드백으로는 향후 학교 가정통신문뿐 아니라 통지서 스캔, 중요 문서 읽기 같은 기능까지 확장해볼 수 있다는 제안이 있었다.

이 부분은 지금 당장 MVP 범위를 넓히는 항목이 아니라, 현재 만들고 있는 시스템의 향후 서비스 확장 방향으로 정리하는 것이 적절하다.

정리하면 아래와 같다.

- 현재 MVP: 학교 알림 이해 AI
- 이후 확장: OCR 기반 문서 스캔, 통지서/고지서/안내문 해석, 행동 지원 기능 강화

즉 지금은 서비스 완성보다 코어 파이프라인 검증이 우선이다.

## 다음 미팅 전까지 필요한 산출물

다음 미팅 전까지 준비해야 할 핵심 산출물은 아래 4가지다.

### 1. 디바이스 기반 데모

- 실기기 기준으로 동작해야 함
- 에뮬레이터나 데스크탑 시연은 제외
- 최소 흐름:
  텍스트 입력 -> 분석 결과 표시 -> TTS 재생

### 2. 베이스 모델 실험 / 탑재 / 추론 결과

- 6개 라벨 기준 데이터셋 구축
- 베이스라인 모델 실험
- 추론 결과 예시 정리
- 성능 지표 정리

### 3. MVP 정의서 및 체크리스트

- 이번 단계에서 구현할 것과 제외할 것 명확화
- 발표 시 보여줄 수 있는 기능 정리
- 각 파트별 진행 여부 체크

### 4. 트러블슈팅 문서

- 기술 선택 이유
- 구현 중 어려웠던 점
- 제한사항과 미완성 범위
- 왜 현재 범위를 이렇게 잡았는지 설명

## MVP 범위

### 포함

- 가정통신문 / 공지사항 텍스트 입력
- 핵심 정보 추출
- 6개 라벨 분류
  - 일정
  - 준비물
  - 제출
  - 비용
  - 건강·안전
  - 기타
- 쉬운 한국어 문장 제공
- 베트남어 번역
- TTS 음성 안내
- 실기기 데모 화면 확인

### 제외

- OCR 기반 이미지 / PDF 인식
- 실제 학교 시스템 연동
- 자동 푸시 알림
- 일정 자동 등록
- 답장 자동 전송

## 데이터 방향

현재 데이터는 6개 라벨 체계로 먼저 고정하는 것이 적절하다.

### 이유

- 목표 데이터 수가 약 150개 수준이기 때문
- 라벨 수를 늘리면 클래스당 샘플 수가 줄어 성능이 불안정해질 수 있음
- 먼저 6개 라벨로 baseline을 만들고, 이후 필요 시 `기타`를 세분화하는 것이 분석과 비교에 유리함

### 현재 목표

- 6개 라벨
- 약 150개 샘플
- 라벨링 기준 문서화
- baseline 실험 진행

## 현재 역할 분담 관점 정리

### 세종

- 데이터 수집 및 라벨링
- 라벨링 기준 정리
- 모델 입력용 데이터셋 구성
- 베이스라인 실험 결과 정리
- 번역 / TTS 연결 정리
- MVP 정의서 / 체크리스트 / 트러블슈팅 문서 초안 작성

### 태수

- FastAPI 서버
- API 엔드포인트 설계
- 분석 결과 반환 구조 정리
- Android와 연결 가능한 형태로 응답 포맷 정리

### 찬영

- Android 실기기 데모 UI
- 입력 화면 / 결과 화면 / TTS 버튼 중심 데모 제작
- 발표용 시연 흐름 준비

## 찬영 파트 진행 방식

현재 찬영님은 개발 환경 세팅과 Git 흐름부터 바로 따라오기 어려운 상태이므로, 당장은 복잡한 협업 방식보다 AI를 활용한 UI 생성 중심으로 진행하는 것이 현실적이다.

즉 찬영님은 아래 방식으로 참여하면 된다.

- AI에게 명확한 프롬프트를 주고 Android UI 코드 생성
- 생성된 코드 중 발표용 데모 화면 중심으로 선택
- 실기기에서 실행 가능한 화면 확보
- 이후 팀에서 API 연결 범위만 최소한으로 맞춤

이 방식은 참여를 유지하면서도 속도를 확보할 수 있다는 장점이 있다.

## 현재 가장 중요한 우선순위

지금은 범위를 넓히는 것보다 아래 3가지를 반드시 확보하는 것이 중요하다.

1. 6개 라벨 기준 150개 내외 데이터셋
2. 베이스라인 모델 실험 결과
3. 실기기에서 보이는 MVP 데모 흐름

이 3가지만 살아 있어도 다음 미팅에서 프로젝트 방향성과 실행력을 충분히 보여줄 수 있다.

## 발표 / 공유용 한 줄 정리

현재는 학교 알림 이해에 집중한 텍스트 기반 MVP를 구현하고, 이후 OCR 문서 인식과 중요 생활 문서 해석까지 확장 가능한 구조를 목표로 한다.

## 1. 공공데이터 활용 (30점)

### 심사 관점

- 출품 아이디어에 공공데이터가 실제로 필요하고 의미 있게 사용되었는가
- 공공데이터가 단순 장식이 아니라 문제 정의, 대상 선정, 기능 우선순위, 확장 전략에 연결되는가

### 현재 위험

SchoolBridge의 핵심 데이터인 가정통신문 3,300장은 팀이 직접 수집한 실데이터입니다.
이는 강점이지만, 이 공모전에서는 **공공데이터 활용 근거**를 별도로 제시해야 합니다.

### 공공데이터 연결 전략

| 데이터 | 기관/출처 | 서비스 연결 방식 | 발표/사업계획서 표현 |
| --- | --- | --- | --- |
| 다문화 학생 현황 | 교육부/교육통계 | 지역별 서비스 필요도, 우선 도입 지역 선정 | 다문화 학생이 많은 지역부터 파일럿 운영 |
| 외국인 주민·국적별 현황 | 법무부/행안부 통계 | 우선 지원 언어 선정, 지역별 기본 언어 추천 | 지역별 주요 모국어 기반 번역/TTS 우선순위 결정 |
| 다문화가족지원센터 정보 | 여성가족부/다누리 | 학부모 상담·오프라인 지원 연계 | 앱에서 가까운 지원기관 안내 가능 |
| 복지서비스 정보 | 복지로/사회보장정보 | 가정통신문 속 바우처·지원금 키워드 감지 시 안내 | 교육 안내와 복지 지원 정보를 연결 |
| 학교 기본 정보 | 학교알리미/교육부 | 학교 단위 도입 및 배포 대상 관리 | 학교별 서비스 적용 가능성 검토 |

### 서류에 넣을 핵심 문장

```text
SchoolBridge는 팀이 수집한 가정통신문 실데이터와 함께, 다문화 학생 현황·외국인 주민 통계·다문화가족지원센터·복지서비스 공공데이터를 결합해 지역별 지원 언어와 우선 도입 대상을 판단합니다.
```

## 2. AI 기술 활용 (15점)

### 우리 강점

| 기술 | 역할 | 심사 대응 포인트 |
| --- | --- | --- |
| KoELECTRA fine-tuning | 할 일 문장 추출 | 자체 학습 모델, Recall 0.868 |
| KcELECTRA fine-tuning | 6개 카테고리 분류 | 자체 학습 모델, Macro F1 0.8374 |
| Claude Haiku | 비정형 문서 정제, sentence_list/role_hint 구조화 | 생성형 AI 활용 |
| NLLB-200 | 9개 언어 번역 | 외부 LLM 번역 의존이 아닌 통제 가능한 번역 파이프라인 |
| Slot Protection + Glossary | 날짜·금액·URL·학교용어 보존 | 번역 품질 통제 구조 |
| ML Kit OCR + OpenCV | 종이 가정통신문 촬영 인식 | 피지컬 AI 요소 |
| Edge-TTS | 다국어 음성 안내 | 접근성 강화 |

### 발표 멘트

```text
저희는 AI를 단일 API 호출로 쓰지 않았습니다. 비정형 문서를 구조화하는 생성형 AI, 직접 학습한 추출·분류 모델, NLLB 기반 번역, OCR과 TTS를 역할별로 분리해 다문화 학부모가 실제로 이해하고 행동할 수 있는 서비스 흐름으로 연결했습니다.
```

## 3. AI 서비스 (15점)

### 구현 근거

- Android 실기기 데모 완료
- 교사/학부모 역할 분리
- HWP/PDF/TXT/이미지 업로드
- 카메라 OCR 기반 종이 통신문 입력
- AI 분석 결과 카드화
- 9개 언어 번역 및 TTS
- 체크리스트, info_cards, calendar_events 제공
- NCP 서버 배포 및 FastAPI API 운영
- self_test 125+ ALL PASS

### 데모 순서

```text
1. 선생님이 가정통신문 업로드
2. 서버가 문장 정제 → 할 일 추출 → 카테고리 분류
3. 학부모 앱에서 모국어 번역 카드 확인
4. 준비물/제출/비용/일정이 체크리스트와 달력으로 표시
5. TTS로 음성 안내 재생
```

### 발표에서 조심할 점

- 화면만 보여주지 말고 "지금 어떤 문제가 해결되는지"를 말하면서 시연
- 9개 언어 지원은 언어별 품질 평가가 아직 제한적임을 솔직히 말하고, 공통 검증 구조를 설명
- 구현되지 않은 복지로 연계는 현재 기능이 아니라 확장 계획으로 명확히 구분

## 5. 발전·사업화 가능성 (20점)

### 확장 경로

| 단계 | 대상 | 방식 |
| --- | --- | --- |
| 1단계 | 협력 학교 | 무료 파일럿, 가정통신문 자동 분석 검증 |
| 2단계 | 교육청/지자체 | 다문화 학생 비율이 높은 지역 중심 B2G 도입 |
| 3단계 | 다문화가족지원센터 | 상담·안내 보조 도구로 제공 |
| 4단계 | 기존 학교 알림 플랫폼 | API/모듈 형태로 탑재 |

### 사업화 논리

- 학교는 다문화 학부모 안내 부담을 줄일 수 있음
- 학부모는 준비물, 제출, 일정, 비용 정보를 놓칠 가능성이 줄어듦
- 교육청·지자체는 다문화 교육 지원 정책의 디지털 실행 도구로 활용 가능
- 기존 알림 플랫폼은 도메인 특화 AI 기능을 빠르게 탑재 가능

## 제출물 문장 후보

### 문제 정의

```text
다문화 가정 학부모는 학교 가정통신문의 행정·교육 용어를 이해하기 어려워 준비물, 제출기한, 비용, 일정 정보를 놓치기 쉽습니다. 이는 학생의 학교생활 참여 격차로 이어질 수 있습니다.
```

### 해결 방식

```text
SchoolBridge는 가정통신문을 AI로 분석해 학부모가 해야 할 일을 추출하고, 다국어 번역·음성 안내·체크리스트·달력 이벤트로 제공하여 교육 정보 접근성을 높입니다.
```

### 공공데이터 활용

```text
다문화 학생 현황, 외국인 주민 통계, 다문화가족지원센터 및 복지서비스 정보를 활용해 지역별 필요도와 지원 언어 우선순위를 설정하고, 향후 복지서비스 안내까지 확장할 수 있습니다.
```

### 사업화 가능성

```text
초기에는 다문화 학생 비율이 높은 학교를 대상으로 파일럿을 운영하고, 이후 교육청·지자체·다문화가족지원센터 및 기존 학교 알림 플랫폼에 API 모듈 형태로 확장할 수 있습니다.
```

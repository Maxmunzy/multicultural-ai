Q&A — 다같이 대답
================================================================

Q. F1이 낮은데 실서비스 가능한가?
→ [윤정] 노이즈가 6.6배라 구조적으로 낮습니다. Recall 0.868이 핵심입니다.
   노이즈가 일부 통과해도 체크리스트에서 지우는 게 중요 정보 놓치는 것보다 낫습니다.

Q. Claude API 비용 문제 아닌가?
→ [태수] 호출당 $0.06, 1단계 전처리에만 씁니다. 자체 추출 확보 시 분리 예정입니다.

Q. 파파고·ChatGPT보다 번역이 더 정확한가?
→ [세종+태수] 번역 정확성은 거대 LLM 우위입니다, 인정합니다.
   저희 강점은 누적 체크리스트·캘린더·FCM — 학부모의 행동 관리입니다.
   번역 품질은 데이터 축적으로 따라잡겠습니다.

Q. 실제 다문화 학부모에게 테스트해봤나?
→ [태수] MVP라 아직 못 했습니다. 8개 학교 실제 통신문으로 학습하고
   galsan unseen 5,388문장으로 평가했습니다. 실사용자 테스트는 다음 목표입니다.

Q. Precision이 0.321로 낮은데, 노이즈 문장이 너무 많이 통과하지 않나?
→ [윤정] 의도적으로 Recall을 높이는 방향으로 설계했기 때문에 Precision이 낮게 나옵니다.
   노이즈가 일부 체크리스트에 올라와도 학부모가 직접 지울 수 있고,
   중요한 할 일을 놓치는 것보다 훨씬 낫다고 판단했습니다.
   Precision은 데이터가 더 쌓이면 함께 개선될 여지가 있습니다.

Q. KoELECTRA를 선택한 이유가 있나? GPT 같은 더 큰 모델을 쓰는 게 낫지 않나?
→ [윤정] CPU 서버에서 실시간으로 추론해야 하기 때문에 작고 빠른 모델이 필수였습니다.
   KoELECTRA는 한국어 도메인에 특화된 사전학습 모델이고,
   파인튜닝만으로도 가정통신문 도메인에서 충분한 성능을 낼 수 있었습니다.

Q. Seen F1은 높은데 Unseen에서 왜 이렇게 떨어지나?
→ [윤정] Seen은 학습 데이터와 같은 분포의 검증셋이라 높게 나옵니다.
   Unseen인 갈산초는 학습에 전혀 포함되지 않은 다른 학교 데이터라
   distribution shift가 발생합니다.
   저희는 Unseen 기준을 실전 지표로 보고, 이 수치를 개선하는 데 집중했습니다.

Q. v4_merged를 학습했더니 오히려 Seen F1이 0.84에서 0.74로 떨어졌다. 왜인가?
→ [윤정] v4 데이터와 기존 val split의 도메인 분포가 달라서입니다.
   val split은 v3.1.3 기준 검증셋인데, v4에 새 학교 패턴이 대거 들어오면서
   모델이 더 다양한 분포를 학습하게 됐고, 기존 val split에서는 소폭 하락했습니다.
   반면 Unseen(galsan) F1은 0.4166에서 0.4687로 올랐습니다.
   실전 일반화가 목표였기 때문에 이 방향이 맞다고 판단했습니다.

Q. 라벨 품질은 어떻게 보장했나? 자동 라벨링만 믿어도 되는가?
→ [윤정] 자동 라벨링 후 반드시 사람이 검수했습니다.
   특히 모델이 확신도가 낮은 경계 케이스는 직접 확인했고,
   소프트 라벨(확률값)을 써서 애매한 문장에 이진 라벨 대신 신뢰도를 부여했습니다.
   완벽하지는 않지만, 경계 케이스를 강제로 0/1로 나누지 않는 방식이 더 안전하다고 봤습니다.

Q. 클래스 불균형(1:6.6)에 어떻게 대응했나? 오버샘플링은 안 했나?
→ [윤정] WeightedCrossEntropy로 학습 시 클래스 가중치를 줬고,
   True 샘플 증강(v3.1에서 +448문장)도 진행했습니다.
   오버샘플링보다 실제 도메인 데이터를 늘리는 게 더 효과적이라 판단해서
   데이터 수집과 라벨링 확장에 집중했습니다.

Q. 갈산초 하나만 Unseen 테스트셋으로 쓰는 건 충분하지 않은 것 아닌가?
→ [윤정] 지적이 맞습니다. 이상적으로는 여러 학교의 held-out셋이 필요합니다.
   갈산초를 쓴 이유는 학습 데이터와 완전히 분리된 유일한 고정 테스트셋이었기 때문입니다.
   다교 held-out셋 구성은 명확한 한계이고, 다음 개선 과제로 두고 있습니다.

Q. 모델이 잘 못 잡는 문장 유형이 있나?
→ [윤정] 네, 두 가지입니다.
   첫째, "신청 기간: 4월 6일~10일"처럼 행동 동사 없이 날짜만 나열된 문장입니다.
   모델 입장에서 할 일인지 정보인지 구분이 어렵습니다.
   둘째, 표나 리스트 형태로 여러 항목이 한 줄에 묶인 문장도 미추출이 발생합니다.
   두 경우 모두 학습 데이터에 해당 패턴이 부족한 게 원인이고,
   데이터 보강으로 해결 가능합니다.

Q. Claude를 "임시"라고 했는데, 언제 자체화할 계획인가?
→ [태수] 구체적인 일정은 정해두지 않았습니다. 솔직하게 말씀드리면,
   현재 가장 빠른 선택이 Claude이고, 자체 HWP/PDF 파싱 모델 개발은
   레이아웃 다양성 문제를 해결해야 해서 추가 연구가 필요합니다.
   단기적으로는 Claude를 유지하면서 실제 서비스 데이터를 쌓고,
   그 데이터로 자체 파싱 모델을 학습하는 방향으로 가려 합니다.

Q. 학교 네트워크가 외부 API 접근을 막으면 어떻게 되나?
→ [태수] Claude 1단계가 인터넷을 필요로 한다는 건 현재 한계입니다.
   그래서 rule-based fallback을 함께 유지하고 있습니다.
   Claude가 실패하거나 응답이 없으면 정규식 기반으로 sentence를 추출하는
   폴백 경로가 코드에 있습니다. 품질은 낮지만 동작은 합니다.

Q. 개인정보 보호 문제는 없나? 학부모 정보가 서버에 저장되는 것 아닌가?
→ [태수] 현재 MVP에서는 체크리스트 상태를 인메모리에만 저장합니다.
   서버 재시작 시 초기화됩니다. 실제 서비스로 가려면 DB 저장과 함께
   개인정보보호법 기준 처리 방침이 필요하다는 걸 인지하고 있습니다.
   통신문 원문은 분석 후 서버에 보관하지 않는 방향으로 설계할 예정입니다.

Q. 데모는 베트남어만 보여줬는데 나머지 8개 언어는 검증했나?
→ [세종] 베트남어를 집중 검증했고, 나머지 언어는 핵심 용어 보존 구조가
   동일하게 적용되는 것을 코드 수준에서 확인했습니다.
   언어별 번역 품질 차이는 NLLB의 사전학습 데이터 양에 따라 달라지고,
   베트남어·중국어·일본어 순으로 품질이 안정적입니다.
   전 언어 정량 평가는 남은 과제입니다.

Q. 8개 학교 데이터가 전국 초등학교를 대표할 수 있나?
→ [찬영+윤정] 솔직히 대표성에는 한계가 있습니다.
   검단, 성남, 송파, 태평 등 수도권 중심이고 지역 편향이 있습니다.
   그래도 학교별로 포맷과 어휘가 다른 데이터를 의도적으로 섞었고,
   모델이 갈산초 unseen에서도 Recall 0.868을 낸다는 게
   어느 정도 일반화를 보여준다고 봅니다.
   더 많은 학교·지역 데이터 수집이 가장 큰 다음 과제입니다.

# MVP 체크리스트

## 목표

다음 미팅 전까지 학교 알림 이해 AI 시스템의 핵심 뼈대를 실기기 기준으로 시연 가능하도록 준비한다.

핵심 기준은 아래 3가지다.

1. 실제로 동작하는 흐름이 있다.
2. 베이스라인 모델 실험 결과가 있다.
3. MVP 범위와 한계가 문서화되어 있다.

## 1. 데이터

- [ ] 라벨 체계를 6개로 확정한다.
- [ ] 라벨 정의를 문서로 정리한다.
- [ ] 목표 샘플 수를 약 150개로 맞춘다.
- [ ] `기타` 라벨 기준을 명확히 정리한다.
- [ ] `importance`, `action_required`, `tts_target` 기준을 통일한다.
- [ ] 학습/검증용으로 나눌 수 있게 데이터 구조를 정리한다.

## 2. 베이스라인 모델

- [ ] 분류용 베이스라인 모델을 선정한다.
- [ ] 6개 라벨 기준으로 학습 또는 추론 실험을 진행한다.
- [ ] 예측 결과 예시를 3개 이상 확보한다.
- [ ] 성능 지표를 정리한다.
- [ ] 결과 해석 문장을 준비한다.

### 결과 정리 시 포함할 내용

- 사용 모델
- 입력 데이터 수
- 라벨 수
- 간단한 성능 지표
- 잘 된 사례
- 헷갈린 사례

## 3. 서버

- [ ] FastAPI 서버가 실행된다.
- [ ] `/health` 응답이 정상이다.
- [ ] 분석용 엔드포인트가 동작한다.
- [ ] 결과 JSON 구조가 정리되어 있다.
- [ ] Android에서 붙일 수 있는 응답 예시가 있다.

## 4. 번역 / TTS

- [ ] 쉬운 한국어 출력 형식이 정리되어 있다.
- [ ] 베트남어 번역 결과를 확인할 수 있다.
- [ ] TTS 버튼 또는 음성 재생 흐름이 있다.
- [ ] 데모에서 사용할 예시 문장을 준비한다.

## 5. 디바이스 데모

- [ ] 실기기에서 앱이 실행된다.
- [ ] 공지사항 텍스트를 입력할 수 있다.
- [ ] 분석 결과를 카드 또는 리스트 형태로 볼 수 있다.
- [ ] 쉬운 한국어 요약이 보인다.
- [ ] 베트남어 번역이 보인다.
- [ ] TTS 버튼이 동작하거나 동작 흐름이 확인된다.
- [ ] 발표용 데모 시나리오를 1개 이상 정리한다.

## 6. 문서

- [ ] 루트 `README.md`가 현재 방향과 맞게 정리되어 있다.
- [ ] `data/README.md`가 6개 라벨 기준과 맞는다.
- [ ] 팀 브리프 문서가 정리되어 있다.
- [ ] 트러블슈팅 문서가 작성되어 있다.
- [ ] MVP 정의와 제외 범위가 정리되어 있다.

## 7. 발표 준비

- [ ] 프로젝트 핵심 문제를 한 문장으로 설명할 수 있다.
- [ ] 왜 학교 알림에 먼저 집중하는지 설명할 수 있다.
- [ ] 왜 6개 라벨로 시작했는지 설명할 수 있다.
- [ ] 향후 확장 방향을 한 문장으로 설명할 수 있다.
- [ ] 실기기 데모 순서를 팀 내에서 맞춘다.

## 최소 완료 기준

아래 항목이 충족되면 다음 미팅 기준 MVP 뼈대는 갖춘 것으로 본다.

- [ ] 6개 라벨 기준 데이터 약 150개 확보
- [ ] 베이스라인 실험 결과 1회 이상 확보
- [ ] 실기기 데모 1개 흐름 확보
- [ ] 핵심 문서 3종 정리
  - 팀 브리프
  - MVP 체크리스트
  - 트러블슈팅 문서

## 발표용 한 줄 요약

우리는 현재 학교 알림 이해에 집중한 텍스트 기반 MVP를 우선 완성하고, 그 위에 OCR 및 중요 문서 이해 기능을 확장하는 구조로 접근하고 있다.

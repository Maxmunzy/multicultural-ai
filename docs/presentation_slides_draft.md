## 3. §1 프로젝트 개요 (5필수 항목)

```
■ 1. 프로젝트 주제 및 선정 배경 / 기획의도
   • 주제: 다문화 가정 학부모용 가정통신문 다국어 변환 + 학부모 서비스
   • 배경: 다문화 초등학생 11.7만 명 (2025), 13년 3.5배 증가
            결혼이민자 한국어 평균 3.89/5 — 읽기·쓰기 가장 약함
   • 기획의도: 학교 번역 서비스 받기 어려운 소수 다문화 가정 지원

■ 2. 특화 포인트 / 기존 유사 서비스 차별화
   • 거대 LLM (Gemini 등): 한 번의 답 → SchoolBridge: 학부모의 일주일 관리
   • 기존 번역 앱: 일반 텍스트 → SchoolBridge: 한국학교 도메인 특화
     · 9개 언어 + 행정·격식 어휘 글로사리 340여
     · 6칩 자동 분류 (일정·준비물·제출·비용·건강·안전·기타)
   • 학부모 서비스 풀스택 — 누적 체크리스트·캘린더·TTS·STT·FCM 푸시

■ 3. 프로젝트 구현 내용 / 컨셉 / 훈련 연관성
   • 자체 모델 3개 + LLM normalizer 임시 1단계
     · KoELECTRA (슬롯) / KcELECTRA (분류) / NLLB+글로사리 (번역)
     · Claude Haiku 4.5 (sentence 추출, 자체화 목표)
   • 풀스택: FastAPI 백엔드 + Android 앱 + NCP CPU 서버
   • 훈련 연관: NLP·딥러닝·CV·풀스택 서비스 디자인 종합

■ 4. 활용 장비 / 재료 / 개발환경
   • 데이터: 8개 학교 가정통신문 3,300+ 장 + 라벨링 6만+ 행
   • 모델: PyTorch + transformers + HF Hub + Mecab
   • 인프라: NCP CPU 서버 + Docker + Firebase Cloud Messaging
   • 안드: Android minSdk 23, ML Kit OCR, OpenCV, SpeechRecognizer

■ 5. 활용방안 / 기대 효과
   • 학부모: 한국어 통신문 9개 언어 자동 변환 → 학교 정보 격차 해소
   • 학교: 별도 번역 인력 없이 다문화 가정 안내 가능 (학교 자체 호스팅 지향)
   • 정책: 다문화 학생 적은 일반 학교의 소수 가정 사각지대 해소
   • 향후: STT 음성 검색 + 캘린더 통합 → 다문화 가정 행정 비서로 확장
```

## 8. §4-② 모델 개요 — 4단계 파이프라인 + 1 임시 전처리

```
■ 입력: 가정통신문 (사진·HWP·PDF)
   ↓
[1단계] 한글·PDF 정돈 ─ Claude Haiku 4.5 (LLM, 임시)
   • 원문 → 깨끗한 sentence_list 정제
   • 임시 단계 — 자체 추출 방식 확보 시 분리 예정

[2단계] 슬롯 추출 ─ 윤정님 KoELECTRA (자체 모델) ⭐
   • 가정통신문 도메인 학습 (47,148 행)
   • 날짜·시간·금액·URL·전화·대상·장소·준비물 추출

[3단계] 카테고리 분류 ─ 경이님 KcELECTRA (자체 모델) ⭐
   • beomi/kcelectra-base 파인튜닝 (15,957 행)
   • 6개 카테고리: 일정·준비물·제출·비용·건강·안전·기타

[4단계] 다국어 번역 ─ 세종님 NLLB + 글로사리 (자체 모델) ⭐
   • NLLB-200 distilled 600M + 한국학교 도메인 글로사리 340여 항목
   • 9개 언어: vi · zh · th · ja · en · ru · ms · mn · ko_easy

   ↓
■ 출력: 학부모 안드 앱
   • 다국어 카드 (칩 분류) + TTS + STT + 푸시 알림 (FCM)
   • 누적 체크리스트 + 캘린더 + 학년별 분리

핵심:
   • LLM은 1단계 전처리만 — 분류·슬롯·번역은 모두 자체 모델
   • 자체 모델 3개 + LLM 전처리 1단계 + 풀스택 안드 = 3주 ML 파이프라인
```

## 9. §4-③ 모델 선정 및 분석 — 자체화 시도 흔적

```
■ 우리 원칙
   • API 비용 0원 + 학교 자체 호스팅 + 한국어 도메인 특화
   • → 작고 빠른 자체 모델 우선

■ 자체화 시도 타임라인 (3주)

  1차 (4/말~5/7) ─ OCR + bbox + 정규식
   • 세종님 layout_json — HWP/PDF 표·셀 위치 보존
   • 태수 OCR bbox highlight + 정규식 슬롯
   • sentence_skeleton.py — HEADER_NORMALIZE_MAP, SLOT_PATTERNS
   • 한계: 학교마다 다른 레이아웃 변형, 자유 서술 헤더 일반화 어려움

  2차 (5/7) ─ 로컬 LLM Ollama PoC (qwen2.5:3b)
   • NCP CPU 서버에 직접 띄움 (자체 호스팅 시도)
   • 한계: CPU 추론 분석 1회 6분+, 정보 누락, 비결정성
   • → 운영 불가, 폐기

  3차 (5/8 결정) ─ Claude Haiku 4.5 임시 도입
   • 가장 빠른 LLM (sentence 추출 8~16초)
   • JSON 따라쓰기 강함, 503 회피
   • 핵심 분류·슬롯·번역은 여전히 자체 모델
   • → 자체 추출 방식 확보 시 LLM 분리 계획

■ 자체 4모델 선정 기준
   ✓ 작고 빠름 — CPU 추론 가능 (학교 자체 호스팅)
   ✓ 한국어 도메인 특화 사전학습 모델
     · KoELECTRA / KcELECTRA / NLLB-200 distilled 600M
   ✓ 우리 데이터 (1.5만~4.7만 행) 로 파인튜닝 가능
```

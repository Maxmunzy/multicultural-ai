# TTS Feature Design

공모전 제출용 기능 설명에서는 TTS를 단순 “문장 읽기”가 아니라, 사용자가 필요한 정보를 듣는 방식으로 정리합니다.

## 기능 방향

| 기능 | 상태 | 설명 |
| --- | --- | --- |
| 전체 번역문 TTS | 기본 기능 유지 | 번역된 가정통신문 전체 내용을 듣고 싶은 사용자를 위한 기본 음성 안내 |
| 핵심 정보 TTS | UI 확정 후 연결 | AI가 추출한 준비물·제출·일정·비용·건강/안전 정보를 짧게 읽어주는 항목별 음성 안내 |
| STT 질의 응답 | UI 확정 후 연결 | “준비물이 뭐야?”, “제출할 게 있어?” 같은 질문을 구조화 데이터 기반 답변으로 연결 |
| 대체 TTS 엔진 | 실험 후보 | Edge-TTS가 듣기 불편한 사용자에게 일부 언어에서 MMS-TTS 대체 음성 후보 제공 가능 |

## 전체 TTS와 핵심 정보 TTS의 차이

| 구분 | 전체 번역문 TTS | 핵심 정보 TTS |
| --- | --- | --- |
| 목적 | 문맥 전체 확인 | 해야 할 일 빠른 확인 |
| 입력 | 번역된 전체 문장 | checklist, info_cards, calendar_events |
| 길이 | 길 수 있음 | 짧은 행동 문장 |
| 예시 | 번역문 전체 재생 | “내일 준비물은 물병과 실내화입니다.” |

## STT 연결 예시

| 사용자 질문 | 참조 데이터 | 응답 예시 |
| --- | --- | --- |
| 준비물이 뭐야? | info_cards.supplies / checklist | 내일 준비물은 물병, 실내화입니다. |
| 제출할 게 있어? | info_cards.submit / checklist | 금요일까지 신청서를 제출해야 합니다. |
| 돈 내야 해? | info_cards.fee | 체험학습비 3만원을 5월 31일까지 납부해야 합니다. |
| 일정이 언제야? | calendar_events | 체험학습은 6월 3일에 진행됩니다. |

## 구현 원칙

- 원문 전체를 다시 LLM에 보내서 답변하지 않습니다.
- 이미 생성된 `checklist`, `info_cards`, `calendar_events`를 우선 사용합니다.
- 답변은 짧고 행동 중심으로 만듭니다.
- 정보가 없으면 “확인된 준비물이 없습니다”처럼 안전하게 답합니다.
- 전체 번역문 TTS는 유지하고, 항목별 TTS는 추가 기능으로 둡니다.

## 공모전 설명 문장

```text
SchoolBridge는 번역된 가정통신문 전체를 음성으로 들을 수 있는 기본 TTS 기능을 제공합니다. 여기에 더해, AI가 추출한 준비물·제출기한·일정·비용 등 핵심 행동 정보만 별도로 짧게 들을 수 있는 항목별 TTS 기능을 설계했습니다. 사용자는 전체 내용을 듣거나, 실제로 해야 할 일만 빠르게 확인하는 두 가지 방식을 선택할 수 있습니다.
```

```text
TTS 엔진은 8개 언어 전체 지원 안정성을 위해 Edge-TTS를 기본으로 유지하고, 음색 선호와 청취 편안함을 고려해 일부 언어에서는 MMS-TTS 기반 대체 음성 후보를 비교했습니다.
```
